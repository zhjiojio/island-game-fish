# island-bakery 开发规范

## 适用范围
约束本项目（孤岛烤鱼店 / island-bakery）的 bug 修复与交付；与 `docs/codeMonkey/specs/` 设计文档并存。PdeMonster 管轮次追溯与防返工，code-monkey 管方案设计文档。

## 基本原则
- 根因优先：不靠删功能、吞异常、写死样例消报错。
- 最小改动：只改已确认方案所需内容。
- 真实自测：没跑过的写「未实测」，不伪造通过。
- 历史可追溯：轮次只追加不篡改。

## 修复流程
复现与验收 → 根因与影响面 → 方案与风险确认 → 最小范围实施 → 自测与回归 → 交付与归档。

## 文档与轮次
- 轮次 ID：`R0001` 起全局递增，以问题索引为准。
- 状态：待确认｜修复中｜待自测｜待用户验收｜已关闭｜已重新打开。
- 区域文档：仅在该区域首次产生实际记录时创建，禁止预建空文档。

## 自测与回归
原问题复现验证、改动区主流程、相关历史回归、边界与重复操作、日志无新增错误、关联区域影响。未实测必须写明原因。

## 禁止事项
表面修复、伪造结果、擅自扩范围、篡改历史、未确认改产品行为。

## 与 code_monkey 等其他规范的关系
code-monkey 设计文档照旧保存在 `docs/codeMonkey/specs/`。冲突时优先：不伪造、不扩范围、不破坏已确认需求、历史可追溯。

## 长期经验（钓鱼区海面）
- 静底板里已画有海水时，动画浪必须先铺**不透明**海色盖死，再叠动效；只靠半透明条带盖静海会反复透底。
- 禁止用大量「薄片 UV 细横条」拼海面——动起来必出横线。
- 切换钓鱼底板前必须**像素验收**是否已烤船、是否有绿罩/浪层占位；禁止只信文件名（R0006 双船；R0007 noboat 绿罩）。
- 底板已烤船时禁止再画船精灵；仅真无船底板（如 seabase/deepbase）才叠船精灵。
- 本对话钓鱼区后续修复默认全程按 PdeMonster 七步执行（用户 2026-11-18 明确要求）。
- 顶部木条/底部地图背包等常驻功能 UI 必须独立透明层绘制在动态海与船兔之上；禁止烤进 seaflat 后再对整张底板做演出平移（R0008）。
- 动态海改造按 C0→C7→C2→C1→C3… 批次推进；第 1 批（C0+C7）未过不得进 C2；第 2 批（C2）未过不得进 C3；每批保留截图/报告，禁止连续叠改。
- 海水基色必须用「行中位数 + 大尺度低通」，禁止左右插值保留旧浪纹；重导蒙版后必须再跑 UI chrome 拆层（R0009）。
- 海域边界只认 sea-mask；鱼/泡沫/水线禁止再用 `seaTop/beachLine/cut` 猜岸线（R0010）。
- 动态海波场必须以纹理 UV 为坐标、向岸低频涌脊为主；禁止 `gl_FragCoord` + 高频 `sin(y*N)`；禁止 cover 边缘全周白光；拍岸泡沫只认 sea-meta 岸距，深海关 swash；可用 `?sea=static` / `?foam=0`（R0014/R0015）。

## 长期经验（烤鱼店合表）

- 合表 `sheetH = rabbitH / hFrac` 的目标是「合表内兔视觉高 ≈ 静帧 rabbitH」；`maxH` 只能防极端出屏，不得压破该对齐。静帧放大后必须同步复核上限（R0015→R0020：0.36 在 960×540 会把 cook 兔压到约 114）。

## 长期经验（玩法提示字）

- 钓鱼 / 椰林 / 烤鱼店等操作提示统一走 `Renderer.drawGuideTip`（暖奶油金粗体 + 慢速流光）；禁止再各自写白/绿/纯棕 textBold 分叉（R0031→R0033）。

## 长期经验（启动加载）

- 首屏必须 `isBootReady`（字帖 + 当前区必需包）后才画玩法；未就绪只 loading，禁止旧 scene JPG / 矢量兜底抢先露脸（R0037）。
- 资源两阶段：先下当前区必需包，齐了再下其余；横屏继续跳过竖屏专用项（R0013）。
