# 孤岛烤鱼店 · 自主迭代 Rubrics 准则

> 版本：v1.1
> 日期：2026-11-03
> 用途：作为 AI 开发/迭代工具的系统约束，实现自主迭代、减少人工反复修 bug
> 变更：v1.1 新增钓鱼/椰林/烤鱼专项验收用例（FISH/COCO/SHOP），对齐设计文档 v0.5 七步钓鱼机制

---

## 一、不可改变的规则（红线）

违反任何一条 = 立即停止迭代 + 上报人工，不可自主绕过。

| 类别 | 规则 |
|------|------|
| 题材 | 孤岛烤鱼店，治愈系手绘 + 轻度像素 |
| 屏幕 | 横屏 16:9，适配手机横握 |
| 语言 | 全部简体中文，禁用繁体字 |
| 核心循环 | 采集（钓鱼/椰子）→ 制作（烤鱼/椰子汁）→ 售卖 → 金币 → 升级，不可改变顺序 |
| 双商品 | 烤鱼和椰子汁必须同时存在，不可合并或删除其一 |
| 经济底线 | 所有售价 > 成本，玩家不可能「越玩越穷」 |
| 离线机制 | 离线自动采集一旦解锁（看 1 广告）永久有效，不可收回 |
| 广告原则 | 不强制看广告，普通制作/售卖不弹广告 |
| 存档 | 金币/库存/等级/解锁进度必须持久化，不可丢失 |

---

## 二、修复优先级

永远先修高优先级，禁止跨级修复（修 P2 时忽略 P0）。

| 优先级 | 定义 | 示例 |
|--------|------|------|
| P0 阻塞 | 功能完全不可用 / 数据错误 / 流程卡死 | 点击无响应、存档丢失、售价负数、无法进入下一区域 |
| P1 数值 | 逻辑正确但数字算错 | 鱼重量转库存数量不对、金币加减错误、经验值算错 |
| P2 体验 | 功能可用但体验不爽 | 动画生硬、缺音效、加载慢、UI 对不齐 |

**修复顺序：P0 全部修完 → 才允许修 P1 → P1 全部修完 → 才允许修 P2**

## 三、体验标准

每条均可自动化检测，作为验收前置条件。

- [ ] **防连点**：一次点击只触发一次计数，快速连点不会重复触发
- [ ] **弹窗克制**：普通制作/售卖不弹窗，只有以下情况允许弹窗：
  - 广告（激励视频/插屏）
  - 升级/解锁（首次）
  - 离线收益领取
  - 每日目标完成
- [ ] **操作反馈**：每次有效操作 300ms 内有视觉反馈（变色/动画/数字跳动）
- [ ] **弹窗可关闭**：所有弹窗必须有明显的关闭按钮（X 或 取消），不可强制观看
- [ ] **库存为 0**：对应制作按钮置灰 + 提示「去钓鱼」「去椰林」，不可点击
- [ ] **自然时长**：单次 session 15-20 分钟内自然结束（不是强制退出）
- [ ] **加载反馈**：任何加载超过 1 秒必须有 loading 提示，不可白屏

## 五、修改边界

| AI 可自主修改 | 必须先问人 |
|--------------|-----------|
| 任何 P0/P1 bug 的修复代码 | 修改核心循环（采集→制作→售卖顺序） |
| 数值微调（±20% 以内：价格、重量、经验、离线产出） | 新增/删除区域或商品 |
| 文案错别字、UI 对齐、颜色微调 | 改变题材、画风、横竖屏 |
| 性能优化（不改变玩法逻辑） | 广告点位增减、离线机制改动 |
| 添加日志/检测代码 | 任何涉及付费/广告 SDK 的改动 |
| 修复体验标准中的不合规项 | 修改阶段门槛时长（0-5/5-20/20-40 等） |
| 钓鱼/椰林/烤鱼的 QTE 参数微调（时机窗口 ±0.5s 内） | 修改钓鱼七步流程的任何一步 |

**问人话术模板**：
```
我准备改 [具体改动]
影响规则：[对应红线/边界]
风险：[低/中/高]
是否继续？
```

## 六、完成定义（Definition of Done）

一轮迭代只有同时满足以下 4 条才算完成：

- [ ] **专项测试**：本轮修改涉及的用例全部通过（含 FISH/COCO/SHOP 专项）
- [ ] **完整回归**：AC1-AC12 全部通过（防止修 A 坏 B）
- [ ] **静态校验**：控制台 error = 0、无未使用变量、包体积 <5MB
- [ ] **打包通过**：能正常打出可运行的包，真机/浏览器打开不白屏

**不满足任何一条 → 不算完成，继续修。**
**同一用例连续 3 次修复仍不通过 → 停止迭代，上报人工。**

```

│              迭代流程                     │
├─────────────────────────────────────────┤
│                                         │
│  1. 接收 bug 报告 / 新需求                │
│       ↓                                 │
│  2. 分类定级（P0/P1/P2）                  │
│       ↓                                 │
│  3. 判断修改边界（自主 / 问人）            │
│       ↓                                 │
│  4. 执行修改                             │
│       ↓                                 │
│  5. 自检（体验标准 7 条）                  │
│       ↓                                 │
│  6. 跑验收用例（AC1-AC12）                 │
│       ↓                                 │
│  7. 全部通过 → 完成                       │
│     任一失败 → 回到 4                     │
│     连续3次失败 → 上报人工                 │
│                                         │
└─────────────────────────────────────────┘
```
