## 0. 结论先行

1. **技术路线可行，不需要再推翻重做。**
   当前「整幅海面蒙版 + 单张全屏海面 quad + 片元着色器」的方向是对的，比之前的切条、UV 平移、半透明矩形盖静海都更接近根治。

2. **但当前只是“能跑”，还不是“可验收”。**
   上一轮完成的是地基：蒙版脚本、seaflat 静态底、`drawDynamicSea()`、海面着色器分支。真正决定观感的波场、海岸泡沫、船兔刚体、鱼群边界还没有完成。

3. **反复返工的核心不是参数没调好，而是四件事一直没被固定：**
   - 海域边界没有唯一真源，代码里同时存在「像素蒙版」和「屏幕几何猜海岸线」两套标准；
   - 蒙版 RGB 里仍保留旧浪纹和抹船痕迹，着色器把这些脏纹理一起放大；
   - 着色器用屏幕坐标 + 高频 Y 向正弦，结构上必然产生横向条带；
   - 没有可重复的截图/帧序列验收，每轮都靠肉眼和“应该好了”，所以同类问题反复出现。

4. **建议的推进方式：**
   先做 C0 验收基线 + C7 UI 拆层，再做 C2 洗蒙版（硬门禁）、C1 统一几何、C3 重写波场，这四步之后再谈泡沫和船兔。**不要继续在现有 `sin(y*20)` 波场上微调 tint / alpha / 条数。**

### 0.1 已确认决策（2026-11-18）

| 决策项 | 结论 | 对方案的影响 |
|--------|------|--------------|
| UI 处理方式 | **B：拆独立透明层** | 顶部木条、底部地图/背包/木质功能区从 seaflat 中拆出；seaflat 只保留天空、山体、沙滩；UI 层在动态海和船兔之上绘制 |
| 海面风格 | **日落水彩风 + 低频大涌 + 近岸碎浪** | 不做镜面反射、不做写实折射；重点是低频大尺度起伏、远海细密、近岸宽浪和手绘色阶 |
| 验收范围 | **一次性验收 4 组** | 横屏浅滩、竖屏浅滩、横屏深海、竖屏深海同一轮全部通过；礁石作为功能断言，不单独占一组 |

### 1.1 节奏复盘：为什么第 2 步没完成就出现了第 3、4 步

这不是“第 2 步验收通过后顺序推进”，而是三件事挤在了同一轮：

| 事实 | 证据 |
|------|------|
| 蒙版与 seaflat 在 20:02 生成 | `sea-mask-land.png`、`ui-skin-fish-land-seaflat.png` 修改时间 20:02 |
| 着色器在 20:04 就接入 | `renderer.js` 修改时间 20:04，`drawDynamicSea()` 已调用 |
| 中间没有任何验收记录 | PdeMonster 无 R0008 轮次；没有截图、diff 或蒙版报告 |
| 第 4 步的船兔/鱼代码来自更早轮次 | R0001–R0007 已存在 `fishingSurfMotion`、`paintFishingBoatSprite`、鱼群循环 |

所以更准确的说法是：

- **第 2 步：生成了文件，但没有通过质量门禁；**
- **第 3 步：为了尽快看到“海在动”，在未验收的蒙版上直接接了现有 shader 分支；**
- **第 4 步：不是新做的，而是复用了前几轮的船兔/鱼代码，只改了少量共用时钟和层序。**

**结论：这个节奏作为“技术验证 spike”可以理解，作为交付节奏不合理。**

原因：

1. 蒙版没验收，shader 的调参目标就是漂移的。蒙版边界差 10px，泡沫和船的水线就永远对不齐。
2. 视觉问题会混在一起：分不清是蒙版脏、波场差、几何猜错，还是船兔/鱼群动了。R0001–R0007 的返工正是这种混合归因。
3. 违反 PdeMonster 的“一次只改一个变量”。上一轮同时改变了资产、shader、层序和角色坐标。

**正确的门禁：C2（蒙版/seaflat 像素验收）不通过，不进入 C3（波场重写），更不进入 C5/C6（船兔/鱼群）。**

## 2. 为什么多轮反复修改仍达不到效果

### 2.1 根因一：海域边界有两套真源

现状同时存在：

- `sea-mask-*.png` 的 alpha：像素级海域覆盖；
- `fishingSeaLayout()`：`seaTop = 330/1152`、`beachLine = 1000/1152`；
- `fishingSeaLeftMask()`：横屏 `cut = 28 / 310`、竖屏 `0.06 + 0.22 * t²` 等硬编码曲线。

鱼的上限、岸线泡沫、船的位置仍在读第二套几何。只要美术底图或屏幕比例变化，两套边界就会错位，表现为“鱼游到沙滩上”“泡沫在 UI 上”“左边多一条静海”。

**结论：海在哪里，只能由蒙版回答。屏幕几何最多用于相机 letterbox，不能再拿来猜海岸线。**

### 2.2 根因二：蒙版 RGB 不是干净海水，而是旧画面的压缩残影

当前 `generate_sea_masks.py` 的做法是：按行用可靠海水像素插值，再做一次高斯模糊。它能去掉船和礁石，但会把旧浪纹、船体抹痕、深浅色带一起保留下来。

证据：`sea-mask-land.png` 中仍能看到明显的横向深色带和船位附近的糊状色块。着色器用 `col = m.rgb * (0.93 + 0.14 * h)`，等于把这些脏纹理随时钟一起“呼吸”，观感必然像贴图在动，而不是水在动。

### 2.3 根因三：当前波场结构本身就会产生横线

片元着色器当前使用：

```glsl
h += sin(y*20.0 - t*1.05 + sin(x*5.2 + 0.7)*0.9) * 0.50;
h += sin(y*13.0 + x*2.2 - t*0.72 + ...) * 0.32;
h += sin(y*31.0 - x*1.7 - t*1.55) * 0.16;
h += sin(y*57.0 + x*8.0 - t*2.30) * 0.07;
```

主要能量集中在 `y` 方向，频率为 13/20/31/57，且没有透视衰减。结果是：

- 远海和近岸浪的尺度一样，缺少“远处细密、近处宽阔”；
- 横向相位连续，容易形成长条状明暗带；
- 旧的“薄片 UV 细横条”问题只是从贴图搬进了 shader。

**这不是调 alpha 能解决的，必须换波场模型。**

### 2.4 根因四：资源没有做像素验收

R0006 的 `noboat` 实际仍烤着船；R0007 的 `noboat` 船位还有绿色蒙版。两次都是“相信文件名”。

本轮同样有风险：`generate_sea_masks.py` 的 `erase_rects=[(20,320,880,590),(900,480,2020,1010)]` 是绝对像素硬编码，换图后可能擦掉真海水或留下旧船边缘。没有像素对比，就无法证明蒙版边界正确。

### 2.5 根因五：船兔不是严格刚体

现在船和兔共用 `bobY / bobRot`，但兔子还会额外叠加 `AnimDriver` 的 `dx/dy/rot`，并且有独立的 `seatX/seatY` 计算。只要待机、抛竿、收线动画带一点位移，兔子就会相对船“漂”。

用户要的是“船 + 兔作为一个整体随浪起伏”，不是“两个物体各自按同一个正弦上下”。

### 2.6 根因六：鱼被当成海面装饰，而不是水下生物

当前：

```js
var swimY = swimmer.y
  + Math.cos(surf.phase * 0.9 + swimmer.phase) * 4
  + surf.bobY * 0.4;
```

鱼跟着海面 bob 上下，且 X 轴在整屏宽度内循环，没有检查该点是否在海里。于是会出现“鱼跟着浪一起浮沉”“鱼游进沙滩/UI”的观感。

### 2.7 根因七：没有可重复的视觉验收

PdeMonster 多轮记录里反复出现“浏览器动效未实测”“静态门禁 PASS”。这不是执行不认真，而是缺少工具：

- 没有固定分辨率；
- 没有固定时间点截图；
- 没有 UI 区域像素 diff；
- 没有“同一位置跨帧必须变化 / UI 跨帧必须不变”的断言。

结果每轮只能靠肉眼描述，修 A 坏 B 无法及时发现。

### 2.8 根因八：底板里烤着 UI，却在收线时整体平移

`draw()` 在收线时设置 `artShiftX = sin(timer/70) * 4`，`paintScene(backdrop, shift, ...)` 会把整张 seaflat（含顶部木条、底部地图/背包）一起平移；随后 HUD 又按固定坐标重画。于是烤进底板的 UI 会在重画 UI 下方滑动，产生重影/错位。

动态海阶段必须把“底板静止”和“演出位移”分开，不能让静态 UI 跟着海一起晃。

## 3. 目标与验收标准

### 3.1 功能目标

| 编号 | 目标 |
|------|------|
| F1 | 静态底板只保留：顶部天空、远山、左上方山体/岸线、沙滩；顶部木条与底部地图/背包等功能 UI 拆为独立透明层；其余海域全部由动态海覆盖 |
| F2 | 海面有连续、非重复的起伏；远海细密、近岸宽阔，无长横线、无矩形分区、无色块接缝 |
| F3 | 海岸线有周期性的白沫/碎浪，泡沫贴合沙滩曲线，不沿 UI 或船洞画白边 |
| F4 | 船和兔子作为同一刚体随浪上下、轻微倾斜；相对位置不漂移 |
| F5 | 鱼在水下自主游动，深度分层，不跟海面 bob 同步，不游出海域、不上沙滩 |
| F6 | 顶部木条、HUD、底部地图/背包、木质功能区、弹窗、按钮始终在动态海与船兔之上，动画期间像素不被海面覆盖 |
| F7 | 横屏、竖屏、浅滩、深海、礁石钓点均使用同一套“蒙版 + 着色器”机制 |

### 3.2 视觉验收

| 编号 | 验收标准 | 判定方式 |
|------|----------|----------|
| V1 | 任意时刻看不到水平长条带 | 3 个时间点截图 + 横向梯度峰值检测 |
| V2 | 山脚到近岸颜色连续，无硬切线 | 沿 5 条竖线采样颜色差 |
| V3 | 沙滩线外无静海块 | 岸线外侧 20px 内不得出现海水色 |
| V4 | 船兔相对位置固定 | 两个标记点跨 2 个浪周期距离变化 ≤ 1px |
| V5 | 鱼始终在水域内 | 每帧采样鱼中心点蒙版 alpha > 0.6 |
| V6 | UI 区域跨帧完全不变 | 顶部 64px、底部 72px 区域 diff = 0 |

### 3.3 技术验收

| 编号 | 标准 |
|------|------|
| T1 | 只有一个海面时钟 `fishingSurfMotion()`；船、兔、浮标共用 |
| T2 | 只有一个海域边界真源：`sea-mask`；代码不得再用 `seaTop/beachLine/cut` 猜海岸 |
| T3 | 着色器使用纹理 UV，不使用屏幕 `gl_FragCoord` 作为波场主坐标 |
| T4 | WebGL 不可用或纹理缺失时，有可见降级提示，不能静默显示脏 seaflat |
| T5 | 单帧只增加 1 个全屏 quad，移动端不明显掉帧 |

```
1. 静态底板 seaflat
   - 天空、远山、左上角山体、沙滩、岸上物件
   - 不再包含顶部木条、底部地图/背包等木质功能区
   - 海域像素压成干净中性海色，不保留旧浪纹
2. 动态海面（shader，一张全屏 quad）
   - 用 sea-mask alpha 裁海域
   - 用 sea-meta 控制深度与岸线距离
   - 日落水彩风：低频大涌 + 方向波 + 深度衰减 + 手绘色阶
   - 岸线碎浪/白沫（仅沙滩侧）
3. 水下鱼群
4. 礁石（仅 reef 且已解锁）
5. 船 + 兔（同一变换矩阵）
6. 鱼线、浮标、抛竿演出
7. 独立 UI 透明层 ui-chrome-{land,port}.png
   - 顶部木条/标题/状态图标、底部地图/背包/木质功能区
8. HUD / 导航 / 弹窗 / 按钮（每帧最后绘制）
```

**关键原则：**

- 海面不切条、不滚图、不叠半透明矩形。
- UI 拆为独立层，绘制在海面与船兔之后；seaflat 不再保留顶部木条和底部地图/背包。
- UI 层与 seaflat 使用同一套 UV/aspect 与锚点，拆图后位置必须与拆分前像素级对齐。
- 底板和海面动画期间不得整体平移；收线等演出只移动船/兔/鱼线等动态层。
- 天空、远山、左上角山体永远不进入动态海 quad。

## 5. 资源与数据契约

### 5.1 `sea-mask-{land,port,deep-land,deep-port}.png`

| 通道 | 含义 | 要求 |
|------|------|------|
| RGB | 海水基色 | 只能保留低频色阶，禁止旧浪纹、船影、抹痕 |
| A | 海域覆盖 | 0 = 沙滩/天空/山体/船洞；1 = 海。UI 区域不再强制挖空，由 ui-chrome 覆盖 |

尺寸与底板保持 1:2（横屏 1024×576，竖屏 576×1024），UV 与 seaflat 完全一致。

### 5.2 新增 `sea-meta-{land,port}.png`

仅动态海需要，尺寸与 mask 一致：

| 通道 | 含义 |
|------|------|
| R | 到沙滩水线的距离（1 = 岸线，向外衰减到 0） |
| G | 水深（0 = 岸线，1 = 远海） |
| B | 泡沫噪声种子/遮罩修正 |
| A | 保留 |

用途：拍岸泡沫只出现在 R 高的地方；深度控制浪幅、频率、颜色和鱼群分层。

### 5.3 `ui-skin-fish-*-seaflat.png`

- 海域像素统一为干净中性海色；
- 不能保留旧浪纹、船影、绿罩、米色占位块；
- 天空、山、沙滩保持原始像素；
- **不包含顶部木条、底部地图/背包/木质功能区**；
- 生成后必须输出 diff 图：除海域外像素变化必须为 0。

### 5.4 新增 `ui-chrome-{land,port}.png`

| 项 | 要求 |
|----|------|
| 尺寸 | 与对应底板一致（横屏 2048×1152，竖屏 1152×2048） |
| 内容 | 顶部木条/标题/状态图标、底部地图/背包/木质功能区、其他必须常驻的木质 UI |
| 背景 | 透明 RGBA，未占用区域 alpha = 0 |
| 对齐 | 与拆分前 seaflat 中的 UI 像素位置误差 ≤ 1px |
| 用途 | 在动态海、船兔之后绘制，确保功能区永远最上层 |

拆分时必须同时记录各按钮热区坐标；拆层不得改变现有点击区域。

### 5.5 版本号

蒙版、meta、seaflat、ui-chrome 每次重导必须同步 bump：

- `sea-mask-*?v=11`
- `ui-skin-fish-*-seaflat?v=11`
- `ui-chrome-*?v=1`
- `renderer.js?v=88+`

禁止只改文件不 bump，导致浏览器命中旧缓存。

### C0｜建立固定截图与断言基线

**目的：** 先让“好不好”可测量，避免下一轮继续靠肉眼。

**动作：**

1. 增加 URL 调试参数（只在开发环境生效）：
   - `?seaDebug=1`：冻结海面时间，允许指定 `&seaT=1.2`；
   - `?seaDebug=mask`：叠加蒙版边界、UI 矩形、鱼/船标记点。
2. 新建 `scripts/verify_fishing_sea.py`：
   - 固定横屏 1280×720、竖屏 720×1280；
   - 固定 4 组场景：横屏浅滩、竖屏浅滩、横屏深海、竖屏深海；
   - 固定 `t0 / t0+800ms / t0+1600ms` 三个时间点；
   - 输出截图到 `docs/_sea-verify/`；
   - 计算 UI 区域跨帧 diff、UI 层与拆分前底图像素对齐、蒙版内采样点跨帧 diff、鱼中心点 alpha、横向梯度峰值。
3. 先跑一遍当前版本，保存为 `baseline/`。

**验收：**

- 能稳定产出 4 组 × 3 个时间点 = 12 张基线图；
- 能输出一份 JSON 报告，包含 UI diff、海域 diff、横线峰值、鱼越界次数；
- 不改任何正式视觉。

**风险：** 调试参数必须默认关闭，不能污染线上。

### C1｜海域几何统一到蒙版

**目的：** 删除“第二套海岸线”。

**动作：**

1. 在 renderer 增加只读工具：
   - `seaMaskAt(x, y)`：采样 alpha；
   - `seaBoundsAtY(y)`：按行扫描得到左右水域边界；
   - `shoreLineAtX(x)`：按列扫描首个 alpha≈1 的 Y。
2. `fishingSeaLayout()` 只保留相机 letterbox 与 `deep` 标记；
   `seaTop / beachLine / farH / nearTop` 不再作为海域判断依据。
3. 鱼群上限、岸线泡沫、船的水线位置，全部改为查询蒙版。
4. `fishingSeaLeftMask()` 标记 deprecated，只保留给旧路径，不再参与新绘制。

**验收：**

- `?seaDebug=1` 下，代码算出的海岸线与蒙版边界误差 ≤ 2px；
- 鱼群采样点 alpha 全部 > 0.6；
- 视觉与 C0 基线相比无变化（除调试叠层）。

**风险：** 蒙版是半分辨率，采样时要做双线性插值，避免边缘锯齿。

### C2｜清洗蒙版 RGB 与 seaflat

**目的：** 去掉“旧浪纹在呼吸”的根源。

**动作：**

1. 重写 `generate_sea_masks.py` 的海水基色生成：
   - 按行取可靠海水像素的**中位数**，而不是跨孔洞插值；
   - 对行颜色做低通滤波，只保留大尺度深浅；
   - 删除任何周期小于 80px 的横向变化；
   - 船位、礁石位用同一行中位数填充，不保留抹痕。
2. `seaflat` 的海域像素改为同一套干净基色；
3. 保留天空/山/沙滩原始像素；顶部木条与底部地图/背包已在 C7 拆出，不再参与 seaflat；
4. 输出三张调试图：
   - `sea-mask-rgb.png`
   - `sea-mask-alpha.png`
   - `seaflat-diff.png`（非海域像素应为纯黑）

**验收：**

- 蒙版 RGB 任一行亮度曲线不得出现 3 个以上连续峰谷；
- `seaflat-diff.png` 中天空/山/沙滩区域全黑；
- 海面静态截图无横向暗带；
- 岸线颜色与沙滩过渡自然，无青色硬边。

**风险：** 过度模糊会丢失近岸浅水层次。保留“深度梯度”，但去掉“浪纹”。

### C3｜重写波场 v1（先不做泡沫）

**目的：** 换掉会产生横线的 `sin(y*N)` 模型，落到已确认的“日落水彩风 + 低频大涌”。

**动作：**

1. 波场坐标从 `gl_FragCoord / u_resolution` 改为 `v_uv`；
2. 增加深度因子：

   ```glsl
   float depth = smoothstep(horizonV, shoreV, v_uv.y);
   float amp   = mix(0.35, 1.0, depth);
   float scale = mix(1.8, 0.8, depth);
   ```

3. 使用 4–5 个不同方向的波，叠加低频 domain warp：

   ```glsl
   vec2 p = v_uv * vec2(scaleX, scaleY);
   p += vec2(noise(p * 0.8 + t * 0.05), noise(p * 0.8 - t * 0.04)) * 0.35;
   h = wave(p, dir1, freq1, t) + wave(p, dir2, freq2, t) + ...
   ```

4. 去掉所有高频 `y*31 / y*57` 项；
5. 风格约束：
   - 远景以 2–3 个大尺度低频涌浪为主，近岸再叠加更宽、更慢的浪；
   - 只做手绘色阶与波峰提亮，不做镜面反射、菲涅尔、环境反射；
   - 颜色沿用当前日落水彩底色，变化幅度控制在 ±8% 以内，避免“电子蓝”；
   - 波峰高光用暖白色小面积点状带，不画连续白线；
6. 保留一个 `?sea=static` 开关，可随时回退到 seaflat。

**验收：**

- 3 个时间点截图中，横向梯度峰值比 C0 基线下降 ≥ 60%；
- 远海与近岸的浪尺度明显不同；
- 画面仍是日落水彩风，不能出现镜面高光或写实反射；
- 连续观察 10 秒无“贴图平移”感；
- 60fps 设备单帧耗时不超过基线 + 2ms。

**风险：** 这是唯一需要“看感觉”的改造点。建议单独验收，不和泡沫混在一起。

---

### C4｜拍岸碎浪与白沫

**目的：** 让浪真正“拍到沙滩上”，而不是沿所有边界描白边。

**动作：**

1. 生成 `sea-meta` 的 R 通道（岸线距离）；
2. 泡沫分两层：
   - **swash**：沿 R 高值区域的周期推进/回退，频率约 0.18Hz；
   - **crest foam**：只在波峰高度超过阈值时出现，碎点状；
3. 泡沫颜色用暖白 `vec3(0.97, 0.99, 0.96)`，避免纯白；
4. 深海 `deepbase` 关闭 swash；
5. 泡沫在 UI 区域会被 ui-chrome 覆盖；不得出现在船洞、礁石遮罩内。

**验收：**

- 白沫只沿海岸线出现，不沿顶部/底部 UI 出现；
- 10 秒内可见至少 2 次明显推进-回退；
- 沙滩外侧无静态白边；
- 深海无岸线泡沫。

**风险：** meta 的岸线距离如果和 mask 不同源，会再次错位。必须同一次脚本生成。

---

### C5｜船兔严格刚体

**目的：** 从“同一个正弦”升级为“同一个变换矩阵”。

**动作：**

1. 提取 `fishingBoatRig(now)`：

   ```js
   {
     x, y,            // 水线锚点
     rot,             // 绕水线锚点
     pivotX, pivotY   // 与水线锚点一致
   }
   ```

2. 船的绘制使用该 rig；
3. 兔子的绘制：
   - 姿势帧（cast/reel/idle）只在**船局部坐标**内变化；
   - 不再把 `AnimDriver.dx/dy` 加到世界坐标；
   - 兔子的 pivot 固定为船的同一个水线锚点；
4. 增加两个调试标记点：船底锚点、兔脚锚点；
5. 保持 R0006/R0007 规则：已烤船底板不画船精灵，seaflat 才画。

**验收：**

- 跨 2 个浪周期，船底锚点与兔脚锚点的相对向量长度变化 ≤ 1px；
- 无第二艘船；
- 兔下无绿色块；
- 抛竿/收线时兔子不脱离甲板。

**风险：** 兔子动画帧本身可能有脚底偏移，需要在局部坐标里补偿，不要用世界坐标硬拉。

---

### C6｜鱼群水下自主游动

**目的：** 鱼不再“跟着浪浮沉”，也不再游上沙滩。

**动作：**

1. 删除 `swimY` 里的 `surf.bobY * 0.4`；
2. 每条鱼有独立：
   - 深度层 `lane`（远/中/近）；
   - 水平速度 `vx`；
   - 轻微垂直摆动 `sin(t * 0.3 + phase) * amp`；
3. 用 C1 的 `seaBoundsAtY(y)` 限制 X 范围；
4. 到达边界后：
   - 优先掉头（更自然）；
   - 或淡出后从另一侧进入（不能瞬移）；
5. 船体附近加一个椭圆排斥区，避免鱼穿过船底；
6. 远海鱼更小、更淡、更慢；近岸鱼更大、更清晰。

**验收：**

- 连续 30 秒，鱼中心点 alpha 始终 > 0.6；
- 鱼不进入沙滩区域；
- 鱼不随船同频上下；
- 至少 4 条鱼同时可见，且不同步。

**风险：** 边界掉头如果太生硬，可改为“接近边界减速 + 缓慢转向”。

### C7｜UI 拆独立透明层（B 方案）

**目的：** 把顶部木条、底部地图/背包等常驻功能区从 seaflat 中彻底拆出，保证它们永远在动态海与船兔之上，并且不随底板位移。

**动作：**

1. 从横屏/竖屏原图各拆一张 `ui-chrome-{land,port}.png`：
   - 顶部：木条、标题、状态图标、装饰；
   - 底部：地图、背包、木质功能区、装饰；
   - 透明背景，只保留 UI 本体与必要阴影；
2. **补底**：UI 拆掉后，seaflat 中原来被 UI 覆盖的区域用天空/海水/沙滩的自然纹理补齐。不能留透明洞或黑色块；
3. `ui-skin-fish-*-seaflat.png` 重新生成，确保不含顶部木条、底部地图/背包；
4. renderer 增加 `paintFishingUiChrome()`：
   - 绘制时机：动态海 → 鱼 → 礁石 → 船兔 → 鱼线/浮标 → **UI chrome** → HUD/弹窗/按钮；
   - 与 seaflat 使用同一套 aspect/letterbox 映射；
5. 取消收线时对 seaflat 的 `artShiftX`；演出位移只作用于船/兔/鱼线等动态层；
6. 点击热区继续使用现有坐标，不改为从图片反推；
7. `?seaDebug=1` 增加：
   - UI 层显示/隐藏开关；
   - UI 矩形与蒙版边界叠加；
   - 拆分前后像素 diff。

**验收：**

- UI 层显示时，与拆分前基线在 UI 区域像素完全一致；
- UI 层隐藏时，底部补底区域无黑洞、无旧 UI 残影；
- 顶部木条、底部地图/背包跨 3 帧像素完全一致；
- 收线时底图与 UI 不滑动；
- 地图/背包热区位置不变，可正常点击；
- 蒙版在 UI 区域 alpha 可以为 1（因为 UI 已在更高层），但海面不得盖住 UI。

**风险：**

- UI 拆除后的补底最容易露馅，尤其是顶部木条下方的天空/山体和底部木牌下方的沙滩；
- 木牌半透明边缘、阴影如果留在 seaflat，会形成“双层木牌”；
- 拆图后必须用像素 diff 对齐，不能只靠肉眼摆放。

### C8｜四组场景一次性验收

**目的：** 按用户确认的范围，同一轮把横屏/竖屏、浅滩/深海全部验收完，避免“横屏好了竖屏坏”。

3. 礁石：
   - 仅 `spotId === "reef"` 且已解锁时绘制；
   - 礁石只做轻微随浪浮动，不做整块位移；

**验收：**

### C9｜性能、降级与归档

**目的：** 可交付、可回滚。

**动作：**

## 8. 方案可行度评估

### 可行

- 蒙版 + 单 quad 着色器是成熟做法，性能开销可控；
- 当前渲染管线已经支持纹理和自定义 shader 分支；
- 底板、蒙版、层序都已接入，不需要重构整个渲染器；
- 船兔、鱼群、UI 都已有独立函数，改动面可控。

### 最大不确定性

1. **C3 的观感**：程序化水面的“水彩感”需要一轮单独调参，不能承诺一次到位；
2. **C2 的蒙版边界**：自动分割在船位、礁石位、岸边木牌附近可能仍需手动画一笔；
3. **C4 的泡沫**：如果 `sea-meta` 与 `sea-mask` 不同源，会重现错位；
4. **C7 的 UI 拆层**：顶部木条/底部木牌拆走后，补底区域可能露馅；半透明边缘和阴影最容易出现“双层 UI”。必须像素 diff 对齐。
5. **C8 的竖屏与深海**：竖屏岸线窄，泡沫容易糊成白边；深海没有岸线参照，波场尺度更容易显假。

### 8.1 五项不确定性的应对预案

| 风险 | 触发条件（什么时候判定“出问题了”） | 先做的隔离 | 备选方案（Plan B） | 止损与升级 |
|------|--------------------------------------|------------|--------------------|------------|
| C3 水彩波场不到位 | 连续 3 轮调参后仍有横向条带、贴图平移感，或颜色与底板明显不融 | 保留 C3 结构版（无横线、有深度），用 `?sea=static` 随时回退；冻结当前参数，不再边调边改 | ① 程序化低频大涌 + 手绘浪花/泡沫贴片混合；② 离线手绘无缝水面高度图，shader 只做流动与色阶 | 3 轮后停止微调，提交 A/B 截图让用户选；不允许无限调参 |
| C2 蒙版边界不干净 | 船位、礁石位、木牌附近连续 2 次出现残留；或代码海岸线与蒙版误差 > 2px | 自动分割结果 + 独立 override 层，不改输出 PNG；保留每次生成的调试图 | 为 4 组各手写一条海岸线多边形，脚本栅格化成 mask；自动结果只作参考 | 2 轮自动修正仍不达标，直接转手写 mask 作为唯一真源 |
| C4 泡沫与蒙版错位 | `sea-meta` 高值区对应 mask alpha < 0.9；泡沫出现在 UI/船洞/礁石上；偏移 > 2px | 先关闭 swash（`?foam=0`），只保留 crest foam；冻结 meta | mask 与 meta 改为同一次脚本、同一份 numpy 数组生成；仍不行则手写 3 条岸线泡沫带 | 2 轮仍错位，降级为“只保留波峰碎沫”，不再做整圈拍岸 |
| C7 UI 拆层补底露馅 | UI 显示时 diff > 0；出现双层木牌/阴影；UI 隐藏时有黑洞或旧 UI 残影；偏移 > 1px | 保留 `?ui=baked` 回退；原 seaflat 不删；先只拆顶部或只拆底部，分两次验证 | ① 加 2–4px 不透明遮边/阴影盖住接缝；② 紧急回退 A 方案（UI 烤在底板上，蒙版在 UI 区 alpha=0，底板不平移） | B 方案 2 轮仍不过，临时回退 A 并记录；不让 UI 拆层长期阻塞海面 |
| C8 竖屏/深海不达标 | 4 组中任意一组连续 2 轮验收失败 | 使用 per-group profile，不改共享常量；先冻结已通过的组 | 竖屏：降低浪幅、缩窄泡沫、让沙滩遮住白边；深海：去泡沫、加长波长、降低对比、加远景雾带 | 某组 2 轮仍不过，用户决定“接受降级”或“延期”；不得静默降低标准 |

### 8.2 通用止损规则

1. **每个风险最多 3 轮**：一轮只改一个变量，每轮必须留截图和 diff；3 轮不过就换方案，不继续微调。
2. **每个风险必须有开关**：
   - `?sea=static`：回退静态海；
   - `?foam=0`：关闭拍岸泡沫；
   - `?ui=baked`：回退 UI 烤底板；
   - `?profile=land-shallow|port-shallow|land-deep|port-deep`：单组调试。
3. **降级必须显式记录**：写明降级内容、影响范围、恢复条件，不能把“没做完”写成“已完成”。
4. **技术方案由开发判断，观感取舍由用户确认**：涉及“水彩感够不够”“白边能不能接受”的，提交 A/B 截图后再决定。
5. **证据包固定**：每组至少 3 个时间点截图、UI diff、mask/meta 调试图、控制台日志；没有证据不进入下一批。

### 不建议

- 继续在现有 `sin(y*N)` 上改 tint/alpha/频率；
- 继续用 `fishingSeaLeftMask()` 的硬编码 `cut` 猜海岸；
- 把泡沫、船兔、鱼群和波场放在同一轮修改；
- 只凭肉眼说“好了”，不保留截图和 diff。

## 10. 已确认决策与执行含义

### 10.1 UI 处理方式：B（拆独立透明层）

执行含义：

- 新增 `ui-chrome-{land,port}.png`，顶部木条与底部地图/背包/木质功能区从 seaflat 拆出；
- seaflat 只保留天空、山体、沙滩与岸上静物；拆走区域需要补底；
- UI 层绘制在动态海、鱼、礁石、船兔之后，HUD/弹窗/按钮之前；
- 地图/背包热区继续使用现有坐标，不从图片反推；
- 底板与 UI 层在动画期间都不得整体平移。

**代价：** 多一次拆图与补底，但后续不会再出现“UI 被海盖住/底板滑动导致 UI 重影”。

### 10.2 海面风格：日落水彩 + 低频大涌 + 近岸碎浪

执行含义：

- 远景 2–3 个大尺度低频涌浪，近岸叠加更宽、更慢的浪；
- 颜色沿用当前日落水彩底色，变化幅度控制在 ±8% 以内；
- 高光只用暖白色小面积点状带；
- 不做镜面反射、菲涅尔、环境反射、写实折射；
- 泡沫是手绘碎浪，不是连续白线。

### 10.3 验收范围：一次性验 4 组

固定 4 组：

| 组 | 场景 |
|----|------|
| G1 | 横屏浅滩 |
| G2 | 竖屏浅滩 |
| G3 | 横屏深海 |
| G4 | 竖屏深海 |

每组固定 `t0 / t0+800ms / t0+1600ms` 三个时间点，共 12 张验收截图。礁石钓点作为功能断言，不单独占一组。
