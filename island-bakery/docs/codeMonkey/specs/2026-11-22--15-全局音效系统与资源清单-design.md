## 1. 目标与原则

1. **全局一个组件**：玩法与 UI 只调语义 ID（如 `SoundManager.play("fish.cast")`），禁止各处硬编码路径。
2. **分层复用**：全局 UI/反馈一套；场景交互按区；BGM 按区（含独立 `build`）。
3. **事件驱动**：在 Collection / Baking / Selling / 建店状态机节点播放，禁止在 render 每帧触发。
4. **节流与优先级**：同 ID 短间隔不叠；循环声可停；多音同时响时金币/结算优先于环境 loop。
5. **生命周期**：`Game.handleHide` 暂停 BGM，`handleShow` 恢复；区切换才换 BGM，弹窗不换曲。

## 2. 架构（实现约定）

```
Game.init
  └─ SoundManager.init()           // 读开关、预加载 P0
currentArea / building 切换
  └─ SoundManager.setArea(area)    // map|fishing|coconut|shop|build → 对应 BGM
UI 命中成功
  └─ SoundManager.play("ui.click") // 统一入口
玩法事件
  └─ SoundManager.play(id)
可选持续声
  └─ playLoop / stopLoop           // grill、wait、reel、海浪环境等
```

目录约定：

```
res/audio/
  bgm/       bgm_map.mp3 …
  ui/        ui_click.mp3 …
  common/    coin / success / fail …
  fish/      …
  coco/      …
  build/     …
  shop/      …
```

API 约定（在现有 SoundManager 上扩展，不另起模块名）：

| API | 行为 |
|-----|------|
| `init()` | 读存档开关；预加载 P0 表 |
| `play(id)` | 查 ID→路径；受 sfx 开关与节流约束 |
| `playLoop(id)` / `stopLoop(id)` | 短循环（烤制、收线、等待等） |
| `setArea(area)` | 切 BGM；同曲不重切 |
| `setBgmEnabled` / `setSfxEnabled` | 已有；可保留音量扩展位 |
| `pauseBgm` / `resumeBgm` | 对齐前后台 |

静音策略（与 `KwaiMedia` 一致）：BGM `obeyMuteSwitch=false`；SFX `true`。H5/小游戏需在首次用户手势后才开始播 BGM。

## 4. 建店音效细则（已确认）

四步：**砍树 → 锯木 → 搭建 → 生火**。同一木作音色，pitch/质感差分，不算新风格族。

| 阶段 | ID | 听感 | 触发 |
|------|-----|------|------|
| 共用点击基线 | `build.hit` | 中性木击（可作 pitch 源） | 兜底 / 预加载主文件 |
| 砍树 | `build.hit_chop` | 略钝 | `buildStage=chop` 每次有效点击 |
| 锯木 | `build.hit_saw` | 略沙、短锯 | `saw` 每次有效点击 |
| 搭建 | `build.hit_assemble` | 略「咔哒」 | `assemble` 每次有效点击 |
| 生火 | `build.hit_fire` + 叠 `build.fire` | hit 略亮 + 轻火苗 | `fire` 每次有效点击；`build.fire` 与 hit **同时**播 |
| 单步完成 | `build.step_done` | 短正向「收束」 | 切下一 `buildStage` |
| 全部完成 | `build.done` | 更亮收束 / 店亮起 | 四步完成、`shopBuilt` |

首版资源最低集：`build.hit`、`build.step_done`、`build.done`；四步差分可先用程序 pitch（若底层暂不支持 pitch，则导出四份短 mp3）。`build.fire` 为 P1，可后补。

与动画对齐：点击播 hit（及 fire）→ 该步 GIF/特效播完且进入下一步时播 `step_done` → 最后一步结束播 `done`（可与 `step_done` 互斥，只播 `done`）。

## 5. 结算音（已确认）

**严格同一** `ui.settle_open`，用于：

- 钓鱼结果清单弹出  
- 椰林本轮采摘结算弹出  
- 离线收益领取弹窗打开  

配套：

| ID | 用途 |
|----|------|
| `ui.settle_open` | 上述三类弹窗打开（唯一） |
| `ui.settle_confirm` | 主 CTA：领取 / 再采一轮 / 去建店 / 确认入库等 |
| `ui.click` | 弹窗内次要按钮、关闭旁路仍可用 |

稀有鱼出结果：仍先 `ui.settle_open`，可额外叠 `fish.rare`（P2），不替换 settle 音。

## 6. BGM 分区（含独立 build）

| Area | 文件 | 气质 | 切换条件 |
|------|------|------|----------|
| `map` | `bgm/bgm_map.mp3` | 开阔海风木屋总览 | `currentArea=map` |
| `fishing` | `bgm/bgm_fish.mp3` | 空旷海浪底 + 轻旋律 | `currentArea=fishing` |
| `coconut` | `bgm/bgm_coco.mp3` | 叶沙、略明亮 | `currentArea=coconut` 且非建店演出主导时 |
| `build` | `bgm/bgm_build.mp3` | 动手木作、活跃度低于 shop | `building=true` 或建店流程场景 |
| `shop` | `bgm/bgm_shop.mp3` | 暖烟火气经营 | `currentArea=shop` 且店已建成、非 building |

规格：MP3，约 128kbps，BPM 70–90，无缝循环，音量默认低于 SFX。弹窗期间可选 BGM duck −20%（P2）。首日无夜晚曲。

可选环境层（P2）：`fish/env_wave_loop.mp3` 低音量与 `bgm_fish` 叠；无则海浪编进 BGM。

## 7. 混音与同时发声规则

| 规则 | 说明 |
|------|------|
| 节流 | 默认同 ID ≥80ms 才允许再播；椰林 `coco.catch` 可 50ms |
| 循环互斥 | 同区同时最多一个 gameplay loop（如 `shop.grill_loop` 与 `fish.reel` 不会同区） |
| 优先级 | `ui.settle_*` / `common.coin` / `common.success` > 玩法 one-shot > loop/环境 |
| Ducking | 结算打开时 loop 可降或停；关闭后恢复（P2） |
| 无效操作 | `common.invalid` 极轻，避免与 `common.fail` 一样重 |

## 10. 优先级与落地顺序

| 批次 | 内容 | 验收 |
|------|------|------|
| **P0** | SoundManager 查表 + setArea；P0 全表埋点；5 轨 BGM；无素材时可用短占位 beep 验证触发点 | 进区换 BGM；点按钮有 click；钓/椰/店/建主流程关键节点有声；三类结算同 `ui.settle_open` |
| **P1** | 补失败/中间态/系统 UI/建店 fire/烤鱼完美差分/顾客离开 | 断线、摔椰、张力、未解锁、体力空有声；建店四步听得出差分 + step/done |
| **P2** | 环境层、稀有鱼、引导、ducking、淡入淡出 | 氛围不抢玩法；连点不炸耳 |

接线模块对照（实现时）：

| 模块 | 主要 ID |
|------|---------|
| `game.js` setArea / hide-show | BGM、pause/resume |
