# 顾客半身裁切修复与丝滑 GIF/帧动画接入

## 背景

加动画后门闩与程序化抖动后：① 顾客贴右缘或进离场时被画布裁切成「半边身子」；② 火炉仍是三角块火苗，不是火星；③ 兔子/顾客整图平移+旋转，像木偶弹射，缺少关节帧。

## 调用链路

1. 顾客进离场 → `customerSlidePoint` 算脚底 → `paintFootSprite(..., clipToCanvas:true)`  
2. 脚底靠近右边界时，精灵一半画出设计宽 → `clipTexturedRect` 裁掉 ← 半身缺失  
3. 兔子走位用线性 `along` ← 起步像弹射  
4. `AnimDriver` 无帧图时用 rot/dy 冒充动作 ← 木偶感

## 根因分析

- **直接根因（半身）**：进离场为防画外溢出开了整段 `clipToCanvas`；脚底终点取在 `width`，人宽约数十像素时必露半身。  
- **直接根因（木偶）**：只有一张静帧，整图晃动无法做出抬手/翻铲/迈步。  
- **根本原因**：缺「按时间轴换帧」的序列帧资源；程序化动效只能做位移级占位。

## 方案设计

### A. 半身修复（本轮立刻改）

1. 进场起点 / 离场走到淡出前：脚底停在「右缘内侧约半身宽」，保证站在边上时全身可见  
2. 等餐到位：`clipToCanvas = false`；仅进离场且身体越界时才裁  
3. 等餐不再强制水平翻转，恢复原立绘朝向

### B. 火炉动态火星（本轮立刻改）

`drawArtStokeFlames`（及烤制阶段）改为底火 + 多粒上升淡出火星，横竖屏共用。

### C. 丝滑动画正确做法：GIF → 序列帧，不是直接播 GIF

快手小游戏只能 WebGL 贴图，**不能**把 GIF 当视频控件播。正确嵌入：

```
制作连贯动作（AE / 即梦 / 即插画逐帧）
        ↓ 导出 GIF 或 PNG 序列（12～24fps，透明底）
        ↓ 拆成精灵表或逐帧 PNG 放入 res/Image/sprites/anim/
        ↓ AnimDriver 按 clip 换 UV/换图（可加帧间交叉淡化）
        ↓ 仍由 Baking/Selling 阶段门闩开播，不抢进度
```

**烤鱼（给你兔子+烤架时）建议一条长镜头拆三段 clip：**

| clip | 内容（连贯关键帧） | 门闩 |
|------|-------------------|------|
| ignite | 持叉靠近 → 拨火 → 火旺 | 生火点击成功 |
| cook | 小幅度翻拨循环（2 拍循环即可） | cooking 进度条 |
| flip | 下铲 → 鱼离网翻转 → 落回 | 翻面点击成功（结算并行） |

制作要点：同一透视、同一脚底、背景透明；相邻帧变化要小（避免跳切）；翻转用 6～10 帧完成，不要 2 帧瞬切。

**椰汁 / 进出场同理：**  
`put_tools → walk(循环) → pick → crack → straw → walk_back → pick_tools`；顾客 `walk_side` 循环 + `wait` 循环。位移仍用现有槽位插值（改 smoothstep），**身体动作交给帧**，位移与帧步行同相更好。

### D. 本轮代码侧

- 修半身与火星；走位改为 smoothstep  
- `AnimDriver` 保留 sheet 字段（cols/rows/frameCount），有图换帧，无图则减弱程序化幅度  
- 不在本轮用网络拉 GIF；不引入 DOM 播 GIF

## 预期效果

- 顾客进场可见全身，到位不缺半边；离场走到右缘内侧再淡出  
- 烤架有持续火星  
- 有序列帧后动作丝滑；无帧时也不再大幅甩整图

### 进度条与翻面关系

- **能联动**：烤制中动画帧相位 = `elapsed/cookDuration`，条走动作走。
- **翻面结算**：条满后仍是现有「翻面绿区点击」判定品质（外焦里嫩）；点击后播 flip 并立刻结算。若要改成「条满自动翻面、取消点击」，需另改玩法。

点火/翻面 oneshot 仍用通用表。
