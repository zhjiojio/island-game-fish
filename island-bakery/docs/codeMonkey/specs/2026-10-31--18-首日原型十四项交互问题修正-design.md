# 首日原型十四项交互问题修正设计

## 背景

首日原型在接到一个椰子后立即建店，且存在无效按钮、制作自动完成、订单固定、结果反馈不清和白色区域收竿仍能成功等问题，需要调整实际状态流程，而非只修改文案。

## 调用链路与问题点

1. 钓鱼或接椰子 → 采集状态更新 → 食材入账。
2. 接到首个椰子 → 立即触发建店。 ← 缺少回合结束与玩家确认。
3. 底部「升级」和自由探索 → 占位提示或无响应。 ← 展示了未实现功能。
4. 制作开始 → 计时器自动推进 → 自动获得商品。 ← 玩家不操作也会成功。
5. 顾客固定点一种商品 → 点击交付。 ← 缺少鱼种、组合和数量变化。

## 根因分析

- 直接根因：采集、制作和售卖使用一次性演示状态，自动跳转和自动完成承担了本应由玩家决定的环节。
- 根本原因：首日闭环只验证了「能跑通」，没有把回合确认、结果反馈、订单需求和库存选择纳入状态设计。

## 方案设计

### 采集与建店

旧流程：钓到鱼 → 接到一个椰子 → 自动建店。

新流程：钓到鱼 → 鱼种与品质结果 → 60 秒接椰子回合 → 回合结算 → [新增] 玩家选择建店或再采一轮 → 建店动画。

- 白色区域开始收竿立即判定鱼逃跑；绿色区域才允许有效收竿。
- 钓鱼增加拉扯、鱼获跃出水面和逃跑动画。
- 三棵椰子树都可点击；掉落位置随机，数量和速度缓慢增加但保持低难度。
- 筐内数量与本回合实际接到的椰子数一致。

### 制作与结果

- 烤鱼：选择具体鱼种 → 连续点击添柴 → 在绿色区域点击翻面；白色区域得到普通品质，不再自动完成。
- 椰子汁：连续点击敲开椰子 → 再点击插吸管 → 明确完成结果。
- 每次制作结束显示品质、鱼种和售价结果，玩家确认后收下。

### 顾客与订单

- 最多两位顾客，点餐包含鱼种、烤鱼和椰子汁的组合及数量。
- 首位引导顾客必点一条已拥有鱼种，保证首日能完成闭环；后续订单完全随机。
- 顾客不会因等待超时离开，交付完整订单后才离场，再补入下一位。

### 导航

- [移除] 首日未实现的「升级」按钮。
- [移除] 无响应的「自由探索」文字。
- 保留可用的地图和背包。

## 预期效果

玩家能清楚理解每一步为什么发生、操作是否成功、获得了什么，以及下一步可以做什么；首日闭环仍保持轻量，不加入后续升级系统。
