# 横屏钓鱼区：动态海域 GIF 加兔 + 整屏接入（保留 UI 交互与抛竿提竿）

> 状态：**已确认并实施；R0020b 验收补丁待用户验收**  
> 范围：仅横屏钓鱼区；竖屏本轮不动  
> 素材源：`assets/界面/全屏皮肤/横屏钓鱼区动态海域底图.gif`（960×540，64 帧）  
> R0020b：座位 foot=(185,250) h=80 + 近舷遮脚；4 张全分辨率 atlas（16 帧×960×540）；鱼 `x≥420`；renderer `?v=114`

---

## 背景

用户提供带海水涌动的横屏全屏 GIF（已烤空船 + 顶栏/地图背包外观）。  
要：在图上加上兔子，用这张动画整屏替换现有「着色器海 + 船精灵 + 静坐兔」观感；地图/背包等点击热区不变；抛竿/提竿动画仍要播。

## 两种方式区别（问 1）

| | **只改 GIF 素材** | **素材 + 接入游戏（本轮采用）** |
|---|---|---|
| 做什么 | 每帧合成兔子，覆盖写回 GIF 文件 | 上左 + 把动画接到横屏钓鱼区运行时 |
| 游戏里看到什么 | **不变**（仍是着色器海/船兔分层） | 横屏直接播这张涌动海（含船+静坐兔） |
| UI | 不涉及 | 画面用 GIF 里烤好的 UI 外观；**点击热区沿用现有坐标** |
| 抛竿/提竿 | 不涉及 | **保留** sheet 叠在船座位上 |
| 适用 | 只要出片/预览 | 真正换掉「不是我要的海」 |

你已选：**整屏用动画 + 交互兼容 + 保留抛竿/提竿** → 走右列。

## 调用链路（现状 → 问题点）

```
横屏进入钓鱼区
  → 画 seaflat 底板
  → drawDynamicSea（着色器涌浪/浪花）     ← 观感不是用户要的海
  → 画船精灵 + 静坐/动作兔
  → paintFishingUiChrome（透明 UI 皮）
  → drawHUD / drawNav（有 chrome 时只叠字，不画矢量底栏）
  → input.js 用固定矩形点「地图/背包」等
```

GIF 现状：空船、无兔、已含 UI 外观与涌动；灯笼位置各帧几乎不动（可固定座位合成）。

## 方案设计

### A. 素材：GIF 每帧加静坐兔

```
源 GIF 每帧
  + hero_rabbit_fish（透明底坐姿）按船舱坐垫对齐
  → 覆盖写回同路径 GIF
  → 另存预览帧到 docs/_sea-verify/gif-rabbit/
```

- 座位：相对船（灯笼锚点）标定；与现网 `fishingRabbitSeatOnBoat` 横屏偏移对齐微调  
- 只烤 **idle 静坐**；不烤抛竿/提竿姿势  

### B. 运行时：横屏整屏播动画（WebGL 不能直接播 GIF）

```
旧：seaflat + 着色器海 + 船精灵 + 静坐兔 + ui-chrome
新（仅横屏）：
  [新增] 动态海域帧序列/多贴图循环 整屏铺满（含船+静坐兔+UI 外观）
  [关]   drawDynamicSea（横屏）
  [关]   船精灵（已烤进动画）
  [关]   静坐兔（已烤进动画）
  [关]   paintFishingUiChrome 视觉层（避免与 GIF 双 UI）
  [留]   input 热区不变（地图/背包/钓具抽屉/抛收线等）
  [留]   drawHUD / drawNav 在 uiSkinChrome 模式下的文字叠层（体力、顶栏数字）
  [留]   抛竿/提竿：charging/cast/bite/reeling 仍 paintFishingRabbit(sheet)
  [留]   鱼线/浮标仍按座位 tip 计算
```

深海/竖屏：本轮不改（仍走原管线）；若横屏深海也要同 GIF，需你另确认（当前 GIF 偏浅滩日落）。

### C. UI 交互兼容（问 2）

- **不改** `input.js` 里地图 `(20, navY+8, 130×48)`、背包 `(170, navY+8, 130×48)` 及钓鱼区其它热区  
- GIF 内木牌/顶栏需与 960×540 设计坐标视觉对齐；若偏了只微调素材或 letterbox，不改热区逻辑  
- 有 chrome 时 `drawNav` 已只画体力字、不盖按钮底图 → 继续走 `uiSkinChrome=true` 路径  

### D. 抛竿/提竿（问 3）

- idle / waiting：不画独立兔（用 GIF 内烤兔）  
- cast / reel sheet 播放时：在标定座位叠 sheet，盖住 GIF 里的静坐兔  
- 结束后回到只显示 GIF 烤兔  

### E. 体积与帧

- 源约 19MB / 64 帧；需拆成游戏可读贴图（按现有 anim sheet 管线）  
- 实施时优先：降帧或分片多贴图循环，避免单张超大 atlas；具体帧数以能流畅循环且包体可接受为准（实施前在预览里定，例如 16～32 帧）

## 预期效果

1. 横屏钓鱼区海水涌动观感与提供的 GIF 一致，船上有静坐兔  
2. 点地图/背包/顶栏相关逻辑与现在一致  
3. 抛竿、提竿仍有独立动画；结束后兔回到船上静坐  
4. 无双船、双 UI、双静坐兔
