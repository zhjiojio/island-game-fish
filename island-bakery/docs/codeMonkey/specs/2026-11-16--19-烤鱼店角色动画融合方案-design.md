# 烤鱼店角色动画融合方案（横竖屏同步）

## 背景

烤鱼店已有制作阶段（生火 → 烤制 → 翻面）、榨汁走位、顾客进离场位移，但兔子与顾客仍是单帧立绘：翻面只靠整只轻微旋转，等待时像纸片，离场是正面平移淡出。本轮先把四类动作设计成可挂到现有阶段机上的动画方案，确认素材形态与改动范围后再编码。

## 调用链路（现状）

1. 玩家点烤鱼 / 椰子汁 → `Baking.start`（开始制作）记下阶段 `stoke` 或 `crack`
2. 烤鱼：`stoke` 等玩家点绿区 → `cooking` 进度条自动走完 → `flip` 等玩家点绿区 → 出餐
3. 椰汁：`crack` 敲三下 → `straw` 插吸管 → 出餐；绘制层用 `elapsed` / `plating.timer` 做兔子去柜台再回来的插值
4. 顾客：进场用 `arrival` 从右侧滑入；交付后 `leaving` + `leaveTimer` 向右平移，到右边界再淡出 ← 无侧身步行、无等待循环
5. 绘制：`drawShopCast`（画烤架/兔子/顾客）一律 `paintFootSprite` 贴单张 PNG；翻面时兔子只加 `rot`，烤鱼用 `scaleY` 模拟翻面

## 已确认决策（2026-11-16）

1. **素材形态**：本轮用精灵表（方案 A）。**Spine 留二期**＝本轮不做骨骼动画；等烤鱼店帧动画跑通、再有 Spine 素材与分层方案时，另开一轮把角色换成 Spine（不是流量/CDN 相关）。
2. **进出场方向**：横竖屏统一从右侧侧身走进，取餐后统一向右侧身走出。
3. **翻面与结算**：点击翻面绿区后**立刻结算出餐**（保持现逻辑）；兔子翻面与烤鱼翻面动画并行播完，不挡结算。
4. **范围**：只接烤鱼店四类（烤鱼 / 椰汁 / 等餐 / 进出场）；钓鱼、椰林本轮不动。
5. **补充**：动物顾客**进场也是侧身走入**（与离场同一套侧身步行，朝向相反即可）。

## 可行性结论

**可以融合进现有小游戏**，且与快手小游戏约束兼容（WebGL1、无 DOM、单机、资源走本地 `res/`）。

本轮路径：**帧动画精灵表（Sprite Sheet）+ 轻量动画驱动器**，挂在现有 `Baking` / `Selling` 状态上。

| 方案 | 优点 | 风险 | 建议 |
|------|------|------|------|
| A. 精灵表 + `AnimDriver` | 与现有脚底贴图、横竖屏槽位、分层顺序直接兼容；包体与制作成本可控 | 需补帧图 | **本轮采用** |
| B. Spine 3.8（工程已引入） | 骨骼更流畅 | 尚无骨骼素材；默认画在帧尾叠加层，难插进「竖屏成品在兔子下」等分层 | **二期再议** |

## 方案设计

### 总原则

1. **玩法状态驱动动画**，动画不单独推进制作进度；进度条与阶段仍由 `Baking` 决定。
2. **点火 / 翻面只在玩家点到对应节点后开播**，不能提前播、点完不能拖到下一拍才播（同帧启动）。
3. **烤制循环只在 `cooking` 阶段播**，与进度条填充同步存在；进度未到翻面阶段绝不播翻面。
4. **横竖屏共用同一套 clip 与驱动**，只换 `ShopLayout.land / port` 脚底锚点与朝向。
5. **缺帧时回退到当前单帧立绘**，不挡玩法。

### 新增模块（拟）

- `package/gameplay/render/anim-driver.js`：按 clip 名取当前帧 UV、是否播完、是否循环
- `package/gameplay/data/shop-anims.js`：clip 表（角色、帧数、fps、是否循环、触发门闩）
- 资源：`res/Image/sprites/anim/` 下横版精灵表（单角色一张或按动作拆张，内容区 ≤512 边长优先）

改动边界（编码阶段）：

- `baking.js`：椰汁阶段细化为走位编排；烤鱼阶段机语义不变，只多发动画事件
- `selling.js`：离场朝向 / 侧身步行时长可对齐；等待无逻辑改动
- `renderer.js` / `drawShopCast`：兔子与顾客改读 `AnimDriver` 当前帧，不再写死单图 key
- `asset-sprites.js` / 资源加载表：登记新图

不改：订单规则、金币结算、热区几何（除非走位锚点微调）、地图与其他场景。

### 1. 烤鱼动画（兔子）

现有阶段：`stoke` → `cooking` → `flip`。

| 阶段 | 玩家操作 | 动画 clip | 门闩规则 |
|------|----------|-----------|----------|
| 空闲 / 选鱼前 | 无 | `rabbit_grill_idle` 循环 | 一直可播 |
| `stoke` 等待点 | 进度条游标 | `rabbit_grill_idle`（持工具待机） | **禁止**播点火 |
| 点中生火绿区瞬间 | `Baking.hit` 成功 | `rabbit_grill_ignite` 一次 | **同帧启动**；播完立刻切烤制循环 |
| `cooking` | 自动进度 | `rabbit_grill_cook` 循环 | 仅此阶段；进度条 `elapsed/cookDuration` 只影响条，不提前切翻面 |
| `flip` 等待点 | 进度条游标 | `rabbit_grill_cook_hold` 或 idle 持铲 | **禁止**播翻面 |
| 点中翻面绿区瞬间 | `Baking.hit` 成功 → **立刻 `finish` 结算** | `rabbit_grill_flip` 一次 | **同帧启动**；与结算并行，播完即停，不回写玩法进度 |
| 出餐后 | plating | 回到 `rabbit_grill_idle` | 若翻面 clip 仍在播，可继续播完再切 idle |

烤网上的鱼：保留现有贴图；`cooking` 可加轻微热浪/抖动；**翻面 scaleY 只在翻面点击成功后启动**（与兔子翻面同门闩），避免「还没点翻面、鱼已经在翻」。结算不因翻面动画未播完而等待。

进度对应关系（业务语义）：

```
点火节点 = stoke 点击成功
烤鱼过程 = cooking 进度条 0→1（循环烤鱼动作）
翻面节点 = flip 点击成功
```

### 2. 制作椰子汁动画（兔子 + 椰子）

在现有「去柜台 / 敲三下 / 插吸管 / 回来」上拆成可播片段；**敲击与插吸管仍必须玩家点击**，走位与放工具可自动。

建议扩展阶段（仅椰汁）：

```
put_tools → walk_to_work → pick_coconut → crack → straw
                 ↓ finish 后 plating 并行
        juice_to_table ∥ walk_back → pick_tools → idle
```

逐步说明：

1. `put_tools`（自动短时）：兔子在烤架脚底播放下烤鱼工具，工具可留在烤架旁挂点
2. `walk_to_work`（自动）：脚底从 `rabbit` 槽插值到柜台前站位点（沿用现有横竖屏 stand 偏移）
3. `pick_coconut`（自动短时）：从青椰堆到 `work` 台面；再进入可点的 `crack`
4. `crack`：每次 `hit` 播一次敲击，椰子沿用抖动；满 3 次后进 `straw`
5. `straw`：点击后播插吸管，再 `finish`
6. plating 前半：成品椰汁飞向椰汁堆锚点；**同时**兔子 `walk_back`
7. plating 后半 / 回到烤架：`pick_tools` 拿回工具，恢复 `rabbit_grill_idle`

横竖屏：走位只读各自 `work` / `rabbit` / 椰汁堆锚点，clip 相同。

### 3. 顾客等餐（按动物单独循环）

触发：`arrival` 收完且未 `leaving`。

现有类型 `otter / cat / rabbit / bear` 映射立绘企鹅 / 狐 / 猪 / 双色熊，**每种独立等待循环，动作题材不重复**：

| 类型 | 立绘 key | 等待动作设计（循环） |
|------|----------|----------------------|
| bear | `customer_bear_*` | 耸肩晃身子 + 偶发打哈欠 |
| otter | `customer_penguin` | 左右跺脚 + 小幅度转头 |
| cat | `customer_fox` | 摇尾巴弧线 + 歪头 |
| rabbit | `customer_pig` | 踮脚换重心 + 耳朵/头轻晃 |

实现：每类 4～8 帧 loop；相位按 `customer.id` 错开，避免两人同帧齐刷。禁止只用透明度闪烁或整图平移冒充「有生命」。

### 4. 顾客进场 / 取餐离场（侧身走）

现状问题：正面立绘水平平移进出，像纸片滑走。

目标（横竖屏统一）：

1. **进场**：`arrival` 期间播 `customer_*_walk_side`，从画面**右侧外**侧身走进槽位；面朝左（向店内），到位后切等待循环
2. **离场**：交付成功当帧仍用同一套侧身步行，面朝右，向**右侧**走出；走到右边界后再短淡出或裁切
3. **不是**正对镜头平移；左右朝向用贴图 UV 翻转区分进出
4. 总时长与换人逻辑对齐（现约 1100ms 离场；进场现约 `arrival` 收完；侧身走若加长需同步改计时）
5. 气泡：进场跟头锚点；离场「谢谢光临」同样跟随，侧身时可微调用头偏移

### 动画驱动与绘制接入

```
Baking / Selling 状态
        ↓
AnimDriver.resolve(actorId, now)
        ↓ 当前 frame UV + facing
paintFootSprite / paintCenterSprite（仍脚底对齐槽位）
```

事件建议（便于日志排查）：

- `baking:qte` 已有 → 追加 `anim:play`（角色、clip、stage）
- 关键节点：`ignite_start` / `flip_start` / `juice_put_tools` / `customer_wait` / `customer_enter_side` / `customer_leave_side`

### 素材清单（需制作或 AI 生图后再导入）

按 [image-spec](../../../../.cursor/skills 不内嵌) 角色建议 ≤512；透明 PNG；横竖屏共用。

兔子：`grill_idle`、`grill_ignite`、`grill_cook`、`grill_flip`、`put_tools`、`walk`（可 2～4 帧）、`pick_coconut`、`crack_hit`、`straw`、`pick_tools`  
顾客 ×4 类：`wait_loop`、`walk_side`（进场/离场共用，靠朝向区分）  
可选：烤架旁放下的工具静帧、敲击时锤/爪残影

无素材前可用「当前立绘 + 既有 rot/shake/lerp」占位，clip 表先接好门闩。

### 新旧流程对比（烤鱼）

旧：

```
stoke 等待 → 点击 → cooking 条 → flip 等待 → 点击 → 出餐
绘制：单帧兔子；flip 时整只晃 + 鱼 scaleY 一直在 flip 阶段循环
```

新：

```
stoke 等待（idle）→ 点击 → [新增] ignite 一次 → cooking（cook 循环）→ flip 等待（hold）→ 点击 → 立刻结算出餐 ∥ [新增] flip 一次（鱼翻面并行）
```

### 新旧流程对比（顾客进出）

旧：正面立绘从右侧滑入槽位 → 静站等餐 → 交付后正面平移向右淡出

新：

```
右侧外 [新增] 侧身走入 → 到位后 [新增] 各自动物等待循环 → 交付后 [新增] 侧身向右走出
```

### 新旧流程对比（椰汁）

旧：开始后兔子插值去柜台 → 敲/插 → plating 插值回烤架（无放/拿工具、无拿椰过程）

新：

```
放下工具 → 走向柜台 → 拿椰上案 → 敲三下 → 插吸管
→ 椰汁飞回桌面 ∥ 兔子走回 → 拿起工具
```

## 预期效果

- 生火、翻面动画只在对应点击成功后出现，烤制循环只出现在进度条烤制段；翻面点击后立刻出餐，翻面动画并行播完
- 做椰汁时能看出放下工具、走动、拿敲插、回位再拿工具；横竖屏动作一致、落点跟各自柜台
- 两位顾客等待时各自动起来，动作不雷同
- 顾客从右侧侧身走进、取餐后向右侧身走出，不再正面平移
- 缺动画资源时玩法与现网一致，只是动作退回静帧

## 修改文件范围（编码时）

- 新增：`package/gameplay/render/anim-driver.js`、`package/gameplay/data/shop-anims.js`、可选 `res/Image/sprites/anim/*`
- 改：`baking.js`（椰汁编排 + 翻面并行动画事件）、`selling.js`（进出场计时对齐，方向统一向右）、`renderer.js`（画兔子/顾客读驱动）、资源加载表 / `asset-sprites.js`、`game.js` 若需 `require` 新文件
- 不改：钓鱼、椰林、订单与金币规则、地图
