# 首日重量库存与离线采集闭环设计

## 背景

玩家按最新版 v0.6 设计钓鱼时，一条鱼应按重量转化为至少两份原料，累计在线二十分钟并看一次广告后可永久离线采集；现原型仍按一条鱼一份原料计算，离线模块还使用旧面包店的面粉、木材和自动售卖逻辑，导致新版流程无法闭环。

本轮经用户确认，保留现有三种鱼、轻松钓鱼手感、二十秒接椰子和分鱼种烤鱼售卖，只增加重量转换、累计在线、广告永久解锁和离线收益，不引入新区域、新鱼种或强制改时长的玩法。

## 调用链路

```text
1. 玩家钓到鱼 → 记录鱼种和品质 → 库存增加一条 ← 缺少重量与份数，和 v0.6 不一致
2. 玩家制作烤鱼 → 消耗一条鱼 → 售出一份 → 金币增加
3. 游戏持续运行 → 帧循环更新采集和制作 ← 没有累计在线和阶段解锁
4. 玩家离线再回来 → 离线模块尝试增加面粉、木材和金币 ← 引用不存在的旧存档字段，且未接入启动流程
5. 玩家重开游戏 → 读取金币、库存和建店进度 → 继续经营（已实测通过）
```

## 根因分析

### 直接根因

- `collection.js`（钓鱼结算）只向库存写入鱼种和品质，`game-state.js`（统一库存）按数组条数计算原料，没有重量及转换份数。
- `offline-manager.js`（离线收益）读取不存在的升级数组，并写入已经删除的面粉、木材字段；启动、离线和回前台流程均未调用它。
- `game.js`（游戏主流程）没有保存累计在线时间、阶段、解锁状态和待领取收益，也没有缺货状态展示。

### 根本原因

原型早期只保存首日经营快照，离线模块是未清理的面包店模板；缺少统一的存档结构升级和阶段状态管理，导致新增规则没有可复用、可恢复的数据入口。

## 方案设计

```text
原流程：钓鱼 → 一条鱼 → 一份原料 → 烤鱼 → 售卖
新流程：钓鱼 → 生成重量 → 计算份数（至少两份）→ 多份同种原料 → 每份独立烤鱼 → 售卖

原流程：持续游玩 → 没有阶段记录 → 离线收益不可用
新流程：持续游玩 → 累计在线二十分钟 → [新增] 可关闭的解锁弹窗
       → 玩家主动看广告并成功 → [新增] 永久解锁、立即保存
       → 关闭或离开 → [新增] 保存离线起点
       → 再次上线 → [新增] 计算鱼肉和椰子收益并弹窗
       → 普通领取 / 成功看广告双倍领取 → [新增] 原子入账、清除待领取收益
```

- 重量：沙丁鱼 1～2kg、青花鱼 2～4kg、金鲷鱼 4～6kg；一公斤约两份，按二倍重量四舍五入且至少两份。一次钓鱼显示鱼种、品质、重量和入库份数。
- 库存：每条鱼保留唯一编号和剩余份数；烤鱼只扣一份，同种鱼合并计数，鱼种、品质和售价规则不变。旧存档兼容为一条一份，新规则只作用于新鱼获。
- 在线：只累计前台实际运行时间，到达二十分钟只弹一次解锁提示；关闭可继续游玩，在地图保留解锁入口。阶段只进不退并持久化。
- 解锁：仅在激励广告成功回调后永久生效，重复点击不能重复触发；取消广告不发奖励。现有原型广告占位回调用于模拟验证，不声称真机广告通过。
- 收益：每小时两份鱼肉、三个椰子，最多累计六小时，即十二份鱼肉、十八个椰子。鱼肉进入默认沙丁鱼原料，椰子单独计数；只在领取时入账，取消或提前关闭广告都不改变库存。
- 存档：统一保存累计在线、解锁状态、离线起点和待领取收益；处理旧存档缺字段、页面离开、回前台和重复领取。已有金币、库存和建店进度继续保留。
- 体验：缺货鱼盘和椰子制作区变灰并提示去对应区域；同一次缺货提醒不刷屏；制作与售卖仍不弹普通完成窗口。新增弹窗均提供明显关闭或稍后按钮。

## 修改范围

- `package/gameplay/data/recipes.js`：鱼种重量区间与转换规则。
- `package/gameplay/play/collection.js`：鱼获生成重量、记录实际入库份数。
- `package/gameplay/core/game-state.js`：份数库存、旧存档兼容、阶段与离线字段保存。
- `package/gameplay/core/offline-manager.js`：替换旧模板逻辑，统一计算与领取离线收益。
- `package/gameplay/core/game.js`：累计在线、解锁选择、收益领取、离开和回前台。
- `package/gameplay/play/input.js`：解锁与收益弹窗操作、防止重复触发。
- `package/gameplay/render/renderer.js`：重量鱼获、缺货反馈、解锁入口与收益弹窗。
- `package/game.js`：仅在确有需要时装配新的阶段模块。
- `docs/ITERATION_RUBRICS.md`、`PROJECT.md`：同步用户确认的规则与本轮验证结果。
- 浏览器验收脚本：首日完整流程、存档重开、重量库存、防连点、离线解锁与收益专项。

不修改平台广告 SDK、AppID、模板配置及未开放区域。

## 预期效果

- 首日：新玩家仍可轻松完成钓鱼、接椰子、建店、制作和售卖；一条鱼能支持多份烤鱼，界面数字与实际消耗一致。
- 存档：重开或回前台不丢金币、库存、等级、建店和解锁进度，不重复发离线收益。
- 二十分钟：玩家可继续当前操作后选择解锁；不看广告也可关闭，成功观看一次后永久有效。
- 离线：普通领取数量准确，看广告双倍准确；取消广告、重复点击和反复打开都不能多领。
- 体验：缺货有明确置灰与去采集提示，连续点击不重复扣体力或弹多层窗口，普通制作售卖保持无弹窗。

## 验收与交付

按 P0 核心闭环和存档、P1 重量及离线数值、P2 缺货与弹窗体验顺序执行。用可控测试时钟覆盖二十分钟和一小时，不真的等待；真实鼠标验证首日闭环，专项验证防连点、旧存档、取消广告、双倍、上限和重复领取。

最后执行 AC1～AC12 等价回归、控制台检查、静态校验并重新打包；明确标注浏览器模拟广告已验证，真机广告与平台权限未验证。
