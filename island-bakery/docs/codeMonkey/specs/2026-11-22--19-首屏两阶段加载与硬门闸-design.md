# 首屏两阶段加载与硬门闸（R0037）

## 背景

刷新进页时，系统只等「当前区一张皮肤」就开画，其它精灵仍在下载；期间会回退到旧版 `scene-*-land.jpg` 或矢量色块，出现残缺旧素材，且全量并发抢带宽让首屏更慢。

## 调用链路

1. `main.js` 每帧 → `Game.update` + `Renderer.draw`
2. `draw` → `loadScenes` 全目录并发入队  
3. `isCriticalArtReady` 只查 1 个 `preferredUiSkinKey` ← **门闸过窄**  
4. 门闸一过 → `backdropKey` 可能回退旧 JPG；区绘制走 `!artOn` 矢量兜底 ← **残缺旧素材**  
5. 字帖与区精灵并行，字未好时「加载中」也不稳

## 根因分析

- **直接根因**：就绪条件过窄 + 未就绪仍画玩法/旧底。  
- **根本原因**：加载策略是「边玩边下」而非「首屏必需包齐再进」；旧 JPG 仍作 backdrop 回退。

## 方案设计

```
旧: 全量并发 → 单皮肤就绪 → 立即画区（可旧 JPG/矢量）
新:
  1. [新增] bootAssetKeys(area) 当前区必需包
  2. [改] loadScenes 两阶段：先只下必需包，齐了再下其余
  3. [改] isBootReady = 字帖 + 必需包全 settled（成功或失败）
  4. [改] 未就绪：只画/HTML loading+进度；不画玩法；挡输入；跳过区 update
  5. [改] backdropKey：UI 皮未失败前禁止回退旧 scene JPG
```

## 预期效果

- 刷新先见 loading，看不到残缺旧素材  
- 首屏必需包下完再进当前区，体感更快（少抢带宽）  
- 进区后后台继续下其它区资源  

## 回滚

恢复单 key `isCriticalArtReady` 门闸与全量并发 `loadScenes`；去掉 HTML `#boot-loading`。
