# 烤鱼合表 maxH 导致兔体跳变 / 对齐静帧（R0020）

## 背景

横屏烤鱼店：未开烤时静帧兔子约高 174；一点烤鱼进入合表动画，兔+炉整体明显变小（截图像顾客蓝熊身高），烤完又回到大静帧，静态→烤制→烤完全程尺度跳变。

## 调用链路

1. 空闲：`drawShopCast` 用 `rabbitH=174` 画 `hero_rabbit_grill` + 单独烤架  
2. 开烤：`AnimDriver` 切到 `combinedGrill` 合表（兔+炉同帧）  
3. 合表高度：`sheetH = rabbitH / hFrac`（lv1 cook 的 `hFrac≈0.59` → sheetH≈295）← **目标是让合表里的兔子视觉高等于 174**  
4. 随后：`maxH = min(画布宽,高) * 0.36`（960×540 → **194**）把 sheetH 夹小 ← **问题点**  
5. 夹紧后兔子视觉高 ≈ `194 * 0.59 ≈ 114`，比静帧矮约 35%；烤完回静帧再跳回 174  

## 根因分析

- **直接根因**：合表缩放在按静帧兔高反推 `sheetH` 之后，又被 `maxH=0.36*min边` 强制压矮，破坏了「合表内兔高 = rabbitH」的对齐。  
- **根本原因**：此前为防合表画出屏加了偏紧的高度上限；R0015 把静帧兔放大到 174 后，上限未同步放宽，静帧与合表尺度脱节。  
- **素材侧**：`grill_lv1_cook` 等 sheet 的 `hFrac` 与像素实测接近（约 0.58–0.64），**不是** GIF/PNG 本身比静帧大一圈；本轮不必改静帧图。  

布局验算（960×540、脚底 74,416）：解除夹紧后 cook `sheetH=295` 顶边约在 y=136，左边贴边经现有 4px 夹紧即可，不挡顶栏、不必然出屏。

## 方案设计

### 推荐：放宽合表高度上限，保住「兔视觉高 = rabbitH」

```
旧: sheetH = rabbitH/hFrac → min(sheetH, min(W,H)*0.36)  ← 横屏压到 194
新: sheetH = rabbitH/hFrac → min(sheetH, min(W,H)*0.56)  ← 横屏上限≈302，cook 295 可通过
    仍保留左右 4px 贴边夹紧与现有 combo 锚点（cxFrac/botFrac）
```

- [改] `renderer.js` `drawShopCast` 合表分支：仅调整 `maxH` 系数（0.36→0.56），不改 `rabbitH`、不改 layout 脚底、不改 sheet 资源  
- [改] 关键日志带上 `maxH` / 是否被夹，便于验收  
- 点火 / 持续烤 / 翻面 / hold 凡 `combinedGrill` 同源，一并受益  
- **不改**静帧 PNG、不改各级 cook sheet 像素  

### 备选（不推荐本轮）

| 备选 | 做法 | 未采用原因 |
|------|------|------------|
| A 改静帧变小对齐夹紧后合表 | 把 `rabbitH` 降到 ≈114 | 抵消 R0015「横屏放大兔」；用户明确要对齐「还没开始烤」的大静帧 |
| B 重绘合表 GIF 填满格 | 让 `hFrac≈1` 再画 | 成本高；根因在上限，不是素材空边 |

## 预期效果

1. 未开烤、生火、烤制中、翻面、烤完回静：兔子身高肉眼一致（≈174）  
2. 合表炉火与静帧烤架相对位置仍靠现有 `cxFrac/botFrac` 锚点，不左右对调  
3. 不改玩法与进度条逻辑；进度条仍可能压在兔手附近（本轮不挪 UI）  

## 回归风险与回滚

- 风险：合表略大时左侧贴边；竖屏若 `rabbitH/hFrac` 仍超新上限会继续被夹（应比现况更接近静帧）  
- 回滚：把 `maxH` 系数改回 `0.36`  

请确认修改文件范围（主要 `renderer.js` 合表 `maxH`）与「对齐静帧大兔、不改素材」后按此实施。
