# 背景

玩家在 **浅滩 + 蚯蚓** 阶段，海面原画仍出现多种装饰鱼，且顾客订单通过 `rollFishSpecies({ spotId, perfect: true })` 与浅滩实际可钓种群不一致，可能点到 **金枪鱼/金色传说** 订单却无法靠钓鱼完成，属于 **逻辑与表现双重割裂**。另开启场景原画（`artOn`）时横屏烤鱼店 **静帧顾客与矢量顾客卡片叠画**。

# 调用链路

1. `Collection.chooseFish` → `Recipes.rollFishSpecies`（钓获）  
2. `drawArtFishingMotion` → 任意 `fish()` 装饰（展示）  ← **与 1 不同源**  
3. `Selling.createCustomer` → `rollFishSpecies`（订单鱼种）  ← **浅滩时可能与可钓不一致**  
4. `drawShop` 横屏 → `drawOrderCustomer` 叠在 `paintScene` 之上  ← **与静帧重复**

# 根因分析

- **直接根因**：`renderer.js` 装饰鱼未读钓点/鱼饵表；`selling.js` 订单 roll 未限定「当前可订单鱼种」；`rollFishSpecies` 在非 `shallow` 分支仍分配金枪鱼等，但 UI 锁定浅滩时不会改写 `spotId`。  
- **根本原因**：缺少 **「可钓/可订单」单一鱼种池**，展示与随机未共用约束。

# 方案设计

1. **[新增]** `Recipes.getOrderableSpeciesIds(spotId, baitId)`：MVP 下浅滩+蚯蚓 → `['small','salmon']`。  
2. **[修改]** `Recipes.rollFishSpecies(options)`：浅滩+蚯蚓时与非完美/完美表一致；礁石/深海未解锁时 **按浅滩处理**，避免脏状态出金枪鱼订单。  
3. **[修改]** `Selling.createCustomer`：首单从库存抽样时 **过滤** 到可订单集合，否则回退到 `rollFishSpecies`。非首单统一走带 `baitId` 的 roll。  
4. **[修改]** `renderer.drawArtFishingMotion`：装饰鱼仅在可展示池（与浅滩一致时为小海鱼/三文鱼）中取种，位置逻辑不变。  
5. **[修改]** `renderer.drawShop` 横屏：若 `artOn` 且烤制区使用静帧，**不绘制** `drawOrderCustomer` 卡片，保留点击区 `630,95` / `630,250`（由 `input.js` 承担）；飘字仍可用。  
6. **[新增]** `island-fish-shop-day1` 平行文件同步，避免双包漂移。

# 预期效果

- 浅滩阶段 **看不到金枪鱼/金色传说** 作为「可钓暗示」的装饰鱼。  
- 顾客订单鱼种 ⊆ 当前钓点可产出（MVP 为 small/salmon）。  
- 原画烤鱼店 **不再双套顾客**；交付仍可通过原热区点击完成。
