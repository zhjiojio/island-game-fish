# 触摸重复计数导致敲椰子次数错误修复设计

## 背景

玩家反馈敲椰子两下就进入插吸管；混合输入复现显示，一次真实触摸和随后的模拟鼠标会让敲击计数从零直接变成二。

## 调用链路

1. 玩家触摸椰子 → `touchstart` → 敲击次数加一。
2. 浏览器补发模拟鼠标事件 → `mousedown` → 再次进入同一敲击逻辑。 ← 同一次点按被计算两次。
3. 第二次真实点按 → 累计四次 → 提前进入插吸管。

## 根因分析

- 直接根因：输入层同时监听触摸和鼠标，但没有过滤触摸后的模拟鼠标事件。
- 根本原因：去重缺失影响所有玩法的点按计数；第三击又立即切换阶段，导致最后一次动作缺少可见反馈。

## 方案设计

旧流程：一次触摸 → 触摸计数 + 模拟鼠标计数 → 两次操作完成三次敲击。

新流程：一次触摸 → [新增] 标记触摸时间 → [新增] 忽略随后模拟鼠标 → 只计一次。

1. 在统一输入层过滤触摸后短时间内的模拟鼠标事件，同时修复其他玩法的潜在重复触发。
2. 每次敲击重置锤击动画，椰子震动并逐步增加裂纹。
3. 第三击后保留约四分之一秒的敲击动作，再进入插吸管阶段；动画期间不多计数。

## 预期效果

- 鼠标点三下、手机点三下，都严格对应三次锤击。
- 两次真实点按不会进入插吸管。
- 第三次敲击有完整动作反馈，然后才出现插吸管提示。
