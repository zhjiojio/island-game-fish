## 背景

动态海着色器用蒙版 RGB 当海水基色再乘浪高。当前蒙版仍保留旧浪纹与船位抹痕：横屏浅滩蒙版抽样行亮度峰谷最高约 15 处，竖屏深海最高约 29 处（验收要求 ≤3）。结果是「旧贴图在呼吸」，不是水在动。

## 调用链路

```
1. generate_sea_masks.py 读一体皮/seabase
2. 判海水覆盖 → 写 alpha
3. 按行插值海水色 + 高斯模糊 → 写 RGB   ← 问题点：插值保留浪纹，σ=20 仍留中频横带
4. 半分辨率输出 sea-mask-*.png
5. seaflat 海域像素替换为同一 col
6. （R0008）split_fishing_ui_chrome 再拆 UI
7. renderer drawDynamicSea：col = m.rgb * (0.93 + 0.14*h)
```

## 根因分析

**直接根因**  
`generate_sea_masks.py` 用左右可靠像素 `np.interp` 填洞，再对整图 `gaussian_filter(σ=20)`。插值会把旧浪纹的横向明暗带原样铺满；σ=20 去不掉周期约几十像素的浪纹。

**根本原因**  
基色生成目标被当成「补洞」，而不是「只保留大尺度深浅」。船位 erase 后仍从两侧脏样本插值，抹痕会留下。

## 方案设计

### 新旧对比

```
旧：逐行 interp(左右海水) → 高斯σ20 → 蒙版RGB/seaflat海区

新：
  逐行取可靠海水像素中位数（船/礁石洞不参与）  [改]
  → 行颜色序列低通（等效去掉 <80px 横向周期）  [改]
  → 纵向再低通，只留远近深浅梯度               [改]
  → 蒙版RGB + seaflat 海区共用这套干净基色
  → 输出 rgb/alpha/seaflat-diff 调试图         [新增]
  → 必须再跑 split_fishing_ui_chrome（保持 C7） [新增门禁]
```

### 具体动作

1. 重写 `generate_sea_masks.py` 的基色段（alpha/岸线逻辑尽量不动，避免本批扩大成 C1）：
   - 每行：`median(valid_pixels)`，valid 不足则借上下近邻行中位数；
   - 行向量做大核低通（目标：横向周期 &lt;80px 的能量压掉）；
   - 船/礁石 erase 区只用该行中位数填，禁止从洞边脏色插值；
2. seaflat 海区继续写同一 `col`；天空/山/沙滩保持源图像素；
3. 生成后立刻跑 `split_fishing_ui_chrome.py`，避免 C7 被回写冲掉；
4. 调试图落到 `docs/_sea-verify/c2/`：
   - `*-mask-rgb.png` / `*-mask-alpha.png` / `*-seaflat-diff.png`
5. 资源 bump：`sea-mask-*?v=12`、`*-seaflat/deepflat?v=12`；`renderer.js?v=89`（仅缓存）
6. `verify_fishing_sea.py` 增加 C2 静态断言：抽样行峰谷数、seaflat 非海区 diff≈0

### 本批明确不做

- 不改波场 shader（C3）
- 不改 `seaMaskAt` 几何统一（C1）
- 不改船兔/鱼群/泡沫（C4–C6）
- 不重拆 UI 规则（沿用 R0008 chrome 脚本）

## 预期效果

1. 静态海面/蒙版基色看不到旧浪纹横带与船位糊斑；
2. 着色器乘浪高时不再「贴图呼吸」；
3. 天空/山/沙滩像素相对清洗前不变（diff 全黑）；
4. C7 的 UI chrome 层仍然在，顶栏底栏不被冲回底板。

## 验收（用户）

1. 硬刷新横屏浅滩：海底色干净，无旧浪纹横向暗带「呼吸」感（浪还会动——本批只洗底色，不改浪怎么画）。
2. 顶栏/底栏仍在，地图背包可点（C7 回归）。
3. 竖屏浅滩扫一眼同样无脏纹。
4. （可选）看 `docs/_sea-verify/c2/` 调试图：蒙版 RGB 应无明显横纹；seaflat-diff 非海区应近黑。
5. 说明：`?sea=static` 本批尚未实现，不要用这个参数验收。
