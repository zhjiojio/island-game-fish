# 在线准则恢复与模板校验修复设计

## 背景

用户要求只按在线 Rubrics 的 AC1～AC12 验收时，发现本地准则被旧流程改写，同时官方模板更新使旧脚手架文件无法通过哈希识别，整包预检报出 47 条错误。

## 调用链路

```text
1. 用户给出在线准则 → 助手读取在线正文
2. 助手又读取本地旧准则并追加规则 ← 两套完成定义混用
3. 验收时引用本地定义 ← 报告没有严格逐项对应 AC1～AC12

1. 官方开发模板更新 → 官方提供新的文件内容与校验指纹
2. 项目仍保留旧版底层文件 → 指纹比对失败
3. 检查工具把底层文件当成自写业务代码扫描 ← 47 条错误来自误判后的扫描
4. 项目主循环含游戏更新与绘制定制 ← 不能整包覆盖或只改指纹
```

## 根因分析

### 直接根因

- `docs/ITERATION_RUBRICS.md`（本地准则）没有与用户在线文档同步，删除了 AC1～AC12 原表和在线完成定义。
- 29 个项目底层文件与当前官方模板指纹不一致；其中多数只有少量官方修正，主循环和预览页则包含项目定制。

### 根本原因

缺少「在线准则是唯一验收来源」的约束，也缺少模板升级时保留项目定制的同步流程；不是玩法逻辑造成 47 个缺陷，也不能通过修改校验指纹掩盖。

## 方案设计

```text
旧验收：本地旧规则 + 在线规则 → 混合结论
新验收：在线原文恢复为本地唯一副本 → AC1～AC12 逐项验证 → 四项完成定义单独检查

旧模板处理：旧底层文件 → 指纹不一致 → 全量误扫描
新模板处理：[新增] 逐文件同步官方修正 → 保留主循环和游戏装配定制
           → 官方整包预检 → 完整玩法回归 → 重新打包
```

## 修改范围

- 将 `docs/ITERATION_RUBRICS.md` 恢复为在线文档的完整原文，不再加入本地规则。
- 同步 26 个不含游戏流程定制的官方底层文件。
- 单独合并 `kwaiStandard/main.js`（主循环）：使用官方安全区封装修正，保留游戏更新、绘制和粒子系统。
- 单独合并 `index.html`（横屏预览页）：同步官方预览修正，保留项目横屏设置。
- 不改 `game.js`、`game.json`、`project.config.json`、玩法代码、广告位 ID、AppID 和校验工具。
- 更新 `PROJECT.md` 与验收记录，按在线 AC1～AC12 输出逐项结果。

## 预期效果

- 后续助手读取本地准则时，与在线版本一致，不再混用完成定义。
- 官方预检能正确识别底层文件，不再把模板能力误判为违规业务代码。
- 游戏仍按原流程运行，首日玩法、存档、离线收益和中文界面不倒退。
- 最终分别报告功能验收、静态校验和打包结果，不把模拟广告或浏览器结果写成真机通过。

## 验证方式

先比对本地准则与在线正文完全一致，再跑官方整包预检；随后从零存档执行 AC1～AC8，通过受控时间执行 AC9～AC12，检查控制台、包体、浏览器非白屏与 ZIP 完整性。真机广告仍单独标注为未验证。
