# 竖屏烤鱼店：顾客热区收窄、成品鱼垫盘、进度条确认

## 背景

竖屏烤鱼店从上到顾客区底边的整条横带都会交付顾客，中层圆木板做椰汁也被算进这块，点椰子就交付了。成品桌上有库存的烤鱼高度约 20 且没有盘子。烤鱼进度条此前已改深橙，本条只确认竖屏仍是深的。

## 调用链路

### 1 · 点击热区（`input.js` 竖屏烤鱼店分支）

1. 玩家点烤鱼店画面
2. 现逻辑：`y` 落在「顶栏下 → 顾客区底」整条横带 → 按左右半屏调用「交付顾客」 ← **问题点：中层圆木板（约画面高度 0.456）落在这条带里**
3. 再判左厨房烤制点击、右 1/3 椰子汁区
4. 预期：先判圆木板周围矩形做椰汁；再判上层两桌顾客脚下两块矩形交付；椰汁区绝不走交付

### 2 · 成品鱼绘制（`renderer.js` 的 `drawShopPlates` / 出餐飞行）

1. 有库存的鱼种 → 在竖屏成品桌四个锚点画烤鱼精灵
2. 现高度约 20，无盘子 ← **问题点**
3. 无库存锚点已跳过不画（保持）

### 3 · 烤鱼进度条

1. 生火 / 翻面走共用进度绘制；烤制走竖屏厨房比例条
2. 填充已是深橙 `C.orange`（与钓鱼张力条同色系）← **已改过，本条只确认竖屏**

## 根因分析

- **直接根因（热区）**：竖屏用「顾客区高度比例横带 + 左右半屏」代替按顾客脚底的矩形，且先于椰汁区判定，把 `port.work`（中层圆木板操作点）吞进交付。
- **直接根因（成品鱼）**：竖屏成品高度写死约 20，且原画层只画鱼不画垫盘。
- **进度条**：竖屏烤制填充与共用进度已用深橙，无需再改色。

## 方案设计

只改竖屏烤鱼店。横屏热区、横屏成品高度与横屏进度逻辑不动。

### 热区（`input.js` 竖屏分支）

旧：

1. 整条顾客横带 → 左右半屏交付
2. 右 1/3 厨房 → 椰汁

新：

1. [新增] 以 `port.work` 为中心的矩形（约横屏同级的 ~115 边长，按竖屏比例落到屏幕坐标）：未做汁 → 开始椰汁；正在做汁 → 烤制点击；**不调用交付**
2. [修改] 顾客热区 = 上层两名顾客脚底附近两块矩形（用 `port.customers` 脚底换算，宽高约盖住桌面/人脚下区域，互不盖到圆木板）
3. [修改] 去掉「整条横带左右半屏」与「右 1/3 厨房当椰汁」旧逻辑
4. 左厨房烤鱼点击、底部选生鱼保持原样

### 成品鱼（`renderer.js`，仅 `portrait`）

旧：高度 20，无盘

新：

1. [修改] 有库存的锚点：先画扁木盘椭圆（无盘子贴图时用浅/深木色椭圆），再画对应 `grilled_*` 成品图，高度约 48，脚底落在盘心（仍用现有脚底绘制）
2. [不变] 无库存锚点不画；四个锚点坐标不挪，避免挡彼此槽位
3. [修改] 竖屏出餐飞行终点鱼高度同步约 48，与桌上一致

### 进度条

1. [确认] 竖屏生火/烤制/翻面填充已是深橙；代码不改色

## 预期效果

- 点中层圆木板只会开始/推进椰汁，不会交付顾客
- 点上层左/右桌顾客脚下矩形才交付对应顾客
- 有库存的鱼在各自锚点下有木盘、鱼高约 48；没货的槽位空白
- 竖屏烤鱼进度条仍是深橙
