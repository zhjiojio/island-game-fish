# 竖屏新船底图抠图替换（保留晃动）

> 状态：已确认并实施（待用户验收）  
> 轮次：R0010 补丁5  
> 横屏：禁止修改

## 背景

竖屏钓鱼区兔子脚下的船精灵 `boat_fish_port.png` 右侧残缺（硬切）。用户新导入完整竖屏小船底图 `package/res/Image/ui/竖屏钓鱼区-小船-底图基地.jpeg`（棋盘格假透明 JPEG），要求：抠出小船主体 → 替换竖屏船底图 → **保留现有随浪晃动**。

## 调用链路

```
1. 资源 boat_fish_port.png（竖屏船精灵）
2. paintFishingBoatSprite（按脚点画船）
3. paintFootSprite + fishingSurfMotion.bobY / bobRot（上下轻晃 + 微旋转）← 动画入口，本次保留
4. 兔子按 fishingRabbitSeatOnBoat 相对船脚叠在甲板上
```

问题点：步骤 1 的图残缺；步骤 3 动画逻辑本身正常，不需要改算法。

## 根因分析

- **直接根因**：现行竖屏船精灵右侧切到船体中间；不是画布宽度临时裁切。
- **根本原因**：旧精灵从一体皮差分裁切时框过紧/源就不完整；应用层无法用脚点「补」出缺失像素。

## 方案设计

```
旧：
  残缺 boat_fish_port.png
  → 脚点 (210,952,h=262) + bobY/bobRot 晃动

新：
  1. [新增脚本] 从 竖屏钓鱼区-小船-底图基地.jpeg 去棋盘格假背景
     → 输出 RGBA PNG，裁主体包围盒，底边硬切保留
  2. [改·仅竖屏资源] 覆盖 package/res/Image/sprites/boat_fish_port.png
     （先备份到 docs/_sea-verify/boat-fix/pre-newboat/）
  3. [改·仅竖屏摆放] 脚点 (270,952,h=252) → 画宽约 528，居中贴底
  4. [改] 兔座位 dx=-55, dy=-118, h=128（左舷坐垫附近甲板）
  5. [改] boat_fish_port?v=10，renderer.js?v=98
  6. 关键日志：首次绘制打印新船脚点与画宽

不改：
  - fishingSurfMotion 晃动公式（bobY/bobRot）
  - 竖屏 seaflat/deepflat 底板
  - 横屏 boat_fish_land 与横屏脚点/水线
  - 动态海、蒙版、UI chrome
```

### 抠图要点

- JPEG 棋盘格是画上去的，不是真 Alpha；用「低彩度高亮连通背景 + 暖色木船主体」去背。
- 主体内浅色坐垫/灯笼高光保留；底部「AI生成」水印在船外，随背景去掉。
- 输出真透明 RGBA PNG，边缘去灰白残边。
