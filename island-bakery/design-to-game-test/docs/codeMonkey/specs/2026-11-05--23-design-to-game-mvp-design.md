# 设计稿到可玩试玩版测试方案

## 背景

《孤岛烤鱼店》设计文档 v0.10 已在附录 E 给出 8 张最终设计稿（横屏 4 张、竖屏 4 张），但设计稿只是静止画面；需要在独立测试项目里把它和已确认玩法合成一段可操作、可验证的小游戏，而不是改动原有项目文档结构。

## 调用链路

1. 设计文档附录 E 设计稿 → 下载到测试项目 `assets/`，横屏只保留 4 张最终稿
2. 独立 Yoola 项目初始化 → 建立单独测试目录和项目状态
3. 设计稿图片 → 压缩到 1280×720 后放入 `package/res/Image/`
4. WebGL 渲染 → 把设计稿作为各场景背景，叠加可交互 UI 和动态玩法层
5. 输入与状态机 → 建立地图、钓鱼、椰林、烤鱼店四个可切换场景
6. 本地 H5 预览 → 验证画面、操作和主循环
7. 遇到 bug → 先自测修复再做交付记录

## 根因分析

不是修复型需求，无根因分析。

## 根因分析（feat 跳过说明）

本次是「设计稿 → 可玩测试样例」的功能验证，目标是找出设计稿转成游戏时的不确定性，不是修复既有缺陷。

## 方案设计

### 设计稿脱壳

1. 附录 E 提取 4 张横屏设计稿。
2. 每张设计稿对应一个试玩场景：
   - 地图页 → 区域选择
   - 钓鱼区 → 甩竿、咬钩、提竿、拉锯
   - 烤鱼店 → 生火、烤鱼、翻面、售卖
   - 椰林区 → 摇树、接椰、产出
3. 保留原设计稿的画面构图，只叠加必要的操作提示与进度条。

### 最小玩法闭环

1. 地图：从 4 张设计稿入口进入对应场景，未玩法不改正式项目。
2. 钓鱼：力度条 + 时机判定 + 拉锯 + 收鱼入库。
3. 椰林：点击树体摇晃，落物计分，控制节奏。
4. 烤鱼店：选择已成库存，烤鱼两段 QTE，卖鱼后升金币。
5. HUD：金币、等级、库存、当前区域、回地图。

### 技术约束

1. 非 DOM 渲染，只用 WebGL。
2. 只用 WebGL 1.0。
3. 所有业务代码放独立测试项目。
4. 图片路径符合 `res/Image/` 与小写连字符命名。
5. 只做桌面浏览器预览加包内交付，不接入真实广告 SDK。

## 预期效果

1. 点击地图 → 能进入钓鱼、椰林、烤鱼店三个场景。
2. 钓鱼后能把鱼肉计入库存，并把数量实时反馈到 HUD。
3. 椰林能接椰子并增加库存/分数。
4. 烤鱼店能把鱼肉转化成可售餐品并计价。
5. 四张设计稿的视觉比例和场景氛围保持一份 16:9 预览一致性。
6. 测试完成后能输出一份「从设计稿到小游戏」的阻挡与结论记录，不回写原设计文档。
