# AI 剧游创作与能力共建平台设计

日期：2026-08-18  
状态：已完成对话评审，等待书面规格确认

## 1. 目标与交付边界

本项目先交付一个可公开访问的高保真交互网页，用于表达未来 AI 剧游创作平台的产品形态。网页必须让首次访问者在一分钟内理解三件事：

1. 个人创作者可以在剧本、人物、视频、游戏组装和发布空间中完成一款剧游；
2. 算法、UI、游戏设计和工程团队在独立的能力共建台中共同生产稳定能力；
3. 平台最终生成并发布快手小游戏生产工程，而不止生成素材或演示视频。

本次交付是产品预期网页，不实现真实 AI 生成、真实多人协作、真实快手上传、计费或生产数据库。所有项目、任务、人物、视频、组件、审核和构建数据均使用可信的演示数据；交互必须足以验证信息架构与核心体验。

源码保存在本技能的 `webapp/` 目录，并可独立部署为公开访问网页。

## 2. 用户与产品定位

平台同时服务个人创作者和制作团队，但默认体验优先照顾不懂代码的个人创作者。

- 新手通过项目总览中的“下一步建议”推进；
- 熟练用户可以自由进入任意专业工作区；
- 团队成员共享项目状态、评论、版本和活动记录；
- 内部算法、UI、游戏设计、工程和审核人员使用另一套能力共建工作台；
- MVP 只允许公司内部成员发布公共能力。

项目采用双入口：

- “AI 从创意开始”：输入一句创意、参考内容和目标体验，生成项目初稿；
- “空白创建 / 导入”：从已有剧本、人物图、视频或小游戏工程开始。

## 3. 总体架构

平台采用“双工作台 + 统一注册中心 + 发布链”架构。

### 3.1 创作工作台

面向个人创作者与项目团队，包含：

- 项目总览；
- 剧本；
- 人物；
- 视频；
- 游戏组装；
- 构建发布；
- 项目资产、项目审计和版本记录。

### 3.2 能力共建台

面向内部能力建设者，包含：

- AI 工具；
- 生产 Recipe；
- 人物与视觉模板；
- 玩法组件；
- UI 组件；
- 预览沙盒；
- 测试与 Evals；
- 版本、审核、发布、停用和回滚；
- 项目使用反馈与优秀产物候选。

### 3.3 统一能力与资产注册中心

所有能力、资产和组件拥有稳定 ID，并记录：

- 不可变版本；
- 贡献者与权限；
- 审核状态；
- 输入输出契约；
- 依赖与兼容范围；
- 项目使用关系；
- 变更说明与回滚目标。

项目锁定所使用的能力和组件版本。公共能力升级不得静默改变已有项目。

### 3.4 构建发布链

发布属于创作平台内部能力，顺序为：

`依赖锁定 → 合规检查 → 资源完整性 → 包体与性能 → 真机验证 → 用户确认 → 快手小游戏上传`

## 4. 核心领域对象

平台必须区分以下四类对象：

### Capability

描述“如何完成或生产一件事”。由内部团队共建、测试、审核和发布。例如人物一致性生成、参考图转视频。

### Asset

能力执行后产生的内容及其版本。例如人物 Master、Anchor v3、视频首帧、最终视频和音频。

### Component

可以进入游戏运行时的玩法或 UI 模块。例如剧情三选一、人物关系反馈、道具交互和卷轴皮肤。

### Instance

资产或组件在某个项目中的一次锁版本使用。例如 `node-12` 使用选择组件 `v1.8` 和卷轴皮肤 `v2`。

稳定引用关系为：

`Story Node → Character Version → Shot Asset → Component Instance → Build Manifest`

## 5. 能力共建模型

人物能力包由算法与 UI/视觉共同生产：

- 算法贡献模型、参数、参考图编辑、身份一致性检查、抠图和放大工具；
- UI/视觉贡献构图、安全区、人物卡模板、风格预设、服装与表情规范、审核对比界面；
- 平台把两者组合成统一输入表单、预览、输出契约、成本时延说明、质量门和测试样例；
- 创作者使用能力后生成项目私有的人物及资产版本。

游戏组件包由游戏设计、经验沉淀、UI 和工程共同生产：

- 游戏设计贡献玩法规则、状态和事件；
- 经验沉淀贡献适用场景、节奏建议、常见失败和验收案例；
- UI/工程贡献视觉状态、皮肤、动效、Canvas 实现和平台适配；
- 平台发布可预览、可配置、可换皮、有契约和自动测试的组件版本。

角色权限按动作授权，不按部门硬编码：

- Owner：定义能力目标、协调贡献并发起发布；
- Contributor：编辑获授权模块；
- Tester：维护样例并运行 Evals；
- Reviewer：独立审核质量、兼容性、成本与合规；
- Admin：管理权限和紧急下线，不代替内容审核。

能力生命周期为：

`Draft → Sandbox → Evals Passed → Independent Review → Published → Deprecated`

项目产物默认私有。优秀结果可提交为公共库候选，经内部审核后沉淀为模板、预设、组件或已授权素材。

## 6. 创作工作台信息架构

### 6.1 全局框架

桌面端采用三栏布局：

- 左侧：项目主导航；
- 中间：当前专业工作区；
- 右侧：上下文检查器或 AI 制作助手；
- 顶部：项目、成员、版本、预览和发布入口。

AI 助手理解当前项目状态并提供可解释建议，但不替代工作区，也不得未经确认跨区修改。

### 6.2 项目总览

展示：

- 下一步建议及原因；
- 剧本、人物、视频、组装和发布完成度；
- 当前阻塞项；
- 一键试玩；
- 最近活动；
- AI 助手提供的高价值动作。

### 6.3 剧本工作区

提供章节列表、剧情节点图、节点检查器、对白与选择编辑、状态变化、结局、搜索过滤、选项专项视图和剧情审计。

节点可直接跳到引用人物、镜头资产和游戏组装位置。

### 6.4 人物工作区

提供项目人物库及以下入口：

- 从公共人物/模板库使用；
- 从项目已有资产复用；
- 上传参考图；
- 使用 AI 人物能力生成。

人物详情展示身份资料、Master、Anchor 历史版本、服装、表情、声线、生成记录、审核状态和所有下游引用。

### 6.5 视频工作区

提供镜头清单与视频资产库，支持：

- 从公共素材库使用；
- 从项目已有素材复用；
- AI 新生成；
- 首帧候选与审核；
- 生成队列、进度、成本与失败恢复；
- 视频版本和采样帧；
- 人物连续性、音画和安全区审核；
- 查看被哪些剧情节点使用。

### 6.6 游戏组装工作区

中心展示 9:16 可玩预览；左侧可浏览剧情节点或代表路径；右侧配置节点绑定、玩法组件、UI 组件、主题、声音和事件。

游戏组件实例同时绑定玩法逻辑、经验说明和 UI 表现。创作者使用统一组件，不处理内部贡献者的模块交接。

### 6.7 构建发布工作区

展示当前锁定版本、发布阻塞项、合规结果、资源完整性、包体、性能、真机测试、版本号、变更说明和上传状态。所有阻塞项可回链到具体对象。

## 7. 用户旅程与确认门

主旅程为：

`双入口 → 项目 Brief → 剧本 / 人物 / 视频 / 游戏组装自由协作 → 构建发布`

四个专业工作区可以自由切换，不要求整个左区全部完成后才能进入右区。以下四个阶段设置必要的人类确认门：

1. 剧本基线：主要角色、核心选择和结局方向；
2. 人物身份：主角 Anchor；
3. 付费生成：代表首帧与成本预估；
4. 正式发布：版本、合规、包体、性能与真机报告。

## 8. 状态、失败恢复与回滚

统一对象状态：

`draft → needs-review → approved → stale → deprecated`

- AI 与媒体任务异步执行，可暂停、重试和恢复；
- Provider 失败只影响当前任务，不覆盖已批准资产；
- 每次生成创建新版本，Master 与已批准版本不可变；
- 上游变化根据依赖关系精准标记受影响对象为 `stale`；
- 能力新版本必须先在沙盒和代表项目中验证；
- 异常版本停止新项目使用，已有项目保持旧版本并支持回滚；
- 发布失败保留构建产物和检查结果，可从失败步骤继续；
- 付费生成、人物身份和正式发布需要用户确认。

## 9. 公开预期网页范围

公开网页应是一个有真实产品感的交互原型，而不是营销落地页。默认打开《荒年记》项目总览，并提供以下可演示页面或状态：

1. 项目总览；
2. 剧本图与节点详情；
3. 人物库与婉儿人物详情；
4. 视频镜头库与首帧审核；
5. 游戏组装与 9:16 预览；
6. 构建发布检查；
7. 能力共建台中的“人物一致性生成”能力详情。

代表交互包括：

- 切换工作区；
- 搜索和过滤剧情节点；
- 打开人物、视频和组件详情；
- 在公共库、项目复用和 AI 生成之间切换；
- 批准/驳回一个首帧；
- 在游戏组装区切换节点并预览选择；
- 展开发布阻塞项；
- 在创作工作台和能力共建台之间切换；
- 查看能力版本、共建成员、Evals 和影响范围。

界面以桌面端专业创作场景为主，支持基本窄屏浏览，但不把移动端复杂编辑作为本次交付目标。

## 10. 视觉方向

整体风格是“电影制作台 + 现代工具软件”，避免普通 SaaS 后台和过度科幻感。

- 深色暖黑背景；
- 黄铜金用于创作、审核与重要行动；
- 冷蓝用于内部能力与算法模块；
- 紫色区分剧本；
- 绿色表示已批准和可发布；
- 红色只用于发布阻塞和高风险失败；
- 大面积内容保持克制，媒体缩略图承担主要视觉吸引力；
- 状态、版本和引用关系必须一眼可辨。

## 11. MVP 验收与测试

产品原型验收：

- 首次访问者一分钟内理解双工作台与快手发布终点；
- 所有主要导航和代表交互可操作；
- 不出现死入口、无反馈按钮或与设计冲突的页面；
- 桌面主视口无横向溢出，窄屏仍可浏览核心信息；
- 页面刷新后能恢复合理的默认演示状态；
- 公共 URL 在无登录状态下可访问。

未来真实平台的黄金项目验收采用《我的未婚妻》的一个代表章节，验证：剧本导入、人物 Anchor、首帧、视频、玩法与 UI 组件、可玩路径、生产构建、真机检查、发布，以及一个优秀产物的审核回流。

异常测试至少覆盖：视频任务恢复、Anchor 升级精准失效、公共组件升级不静默覆盖、角色权限、发布失败续跑和稳定构建回滚。

## 12. 明确不做

- 不开放外部能力市场；
- 不允许所有创作者公开发布能力；
- 不做交易、计费和收益分成；
- 不做任意 Agent/Workflow 图编排器；
- 不做专业非线性视频剪辑器；
- 不做多平台发布；
- 不做模型训练平台；
- 不做通用游戏引擎；
- 不做复杂实时多人共同编辑；
- 本次公开网页不调用真实付费生成和真实发布 API。

## 13. 实施原则

先完成一条高质量“黄金路径”网页，再补齐其他页面，避免先建设空泛组件库。公开网页应使用一致的演示数据、稳定对象 ID 和版本关系，使人物、视频、剧情节点、组件和发布阻塞能够相互跳转。

部署前必须完成本地构建、交互检查、关键视口截图检查和公开 URL 访问验证。
