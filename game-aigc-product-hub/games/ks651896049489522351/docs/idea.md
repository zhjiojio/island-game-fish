# 游戏创意摘要

## 游戏名

斗地主联机小游戏（内部工程名：`dou-di-zhu`，APPID：`ks651896049489522351`）。本次是既有项目的机器人出牌能力升级，不新增题材、角色、美术或客户端玩法。

## 参考玩法与玩法合同

- 三名玩家使用一副 54 张牌进行回合制对局，阵营为一名地主对两名农民。
- 固定主流程：匹配或进入房间 → 准备 → 叫/抢地主 → 加倍 → 出牌 → 服务端结算。
- 服务端是牌局唯一权威：发牌、行动者、牌型校验、胜负、倍率、资产变化均由 Node.js 服务判定。
- 客户端只负责展示、输入和 WebSocket 通信，不直接访问机器人模型。
- 本次只允许改变机器人在 `playing` 阶段如何从服务端生成的合法候选中选择动作。
- 叫地主、抢地主、加倍、牌型规则、回合推进、客户端协议、匹配、钱包和结算均保持不变。
- DouZero 超时、异常、响应非法、模型缺失或服务不可用时，必须自动使用现有规则 AI 完成行动。
- 模型不得获知其他玩家真实手牌，不得自行构造动作，不得绕过 Node.js 的最终规则校验。

## 题材换皮映射

本次不进行题材改造或素材生成。既有牌桌、牌面、角色称谓和中文 UI 保持不变；DouZero 仅作为服务端内部决策引擎，不对玩家展示第三方项目名称、标识、模型素材或宣传内容。

## 目标平台与单局规格

- 平台：快手小游戏；同时保留 H5 本地调试入口。
- 方向与输入：现有 Canvas 布局和触控/鼠标输入保持不变。
- 联机：客户端继续只连接 Node.js WebSocket 服务。
- 人数：每局三人，允许真人与服务端机器人混合匹配。
- 单局规格：沿用当前阶段计时、超时托管、断线处理和结算规则。
- 部署：同一项目内包含 Node.js 游戏服务和 Python/ONNX 推理 Sidecar，以一个 Compose 发布单元共同部署；Sidecar 不得阻塞 Node.js 启动。

## 目标用户与核心指标

- 目标用户：现有休闲三人牌类用户。
- 首要体验目标：机器人在复杂牌型、残局和农民协作场景中做出更合理的出牌。
- 稳定性指标：模型故障时牌局完成率不得低于现有规则 AI 基线，模型导致的最终非法动作必须为 0。
- 性能指标：推理默认 800 ms 超时且不重试，模型耗时计入机器人既有思考时间。
- 可观测指标：每次机器人最终动作可识别实际使用 `douzero` 或 `rule`；降级时可识别有限枚举的原因，但不记录手牌、完整请求或用户身份。
- 风控指标：客户端协议、真人胜率、局时、资产守恒和异常结算率不得因接入发生不可接受的漂移。

## 标题、广告文案与首帧承诺

本次没有标题、广告文案或首帧素材变更，也不以“AI 必胜”“智能赢钱”等表述对外宣传。机器人能力升级只作为内部技术能力，不改变现有广告承诺和用户入口。

## 测试证据

- 现有项目已有规则、机器人、并发锁、匹配和完整牌局测试，可作为回归基线。
- 接入必须新增：牌值与座位编码、公开历史、牌数守恒、候选 ID、HTTP 超时与异常、非法响应、熔断、过期响应和调度守卫测试。
- 在没有经过许可证审核的三份 ONNX 权重时，只交付可运行的空模型 Sidecar：健康检查可用但 readiness 为未就绪；Node.js 自动使用规则 AI。
- 真实权重上线前必须完成三个相对位置的金样例和影子流量验证，再按整局灰度启用。

## 风险与授权检查

### 相似玩法与开源边界

该项目采用通用斗地主规则，与市场上的同类产品存在机制相似。已知类似产品包括：欢乐斗地主、JJ 斗地主、途游斗地主、博雅斗地主和天天斗地主。它们仅用于说明玩法类别与合规风险，不作为代码、美术、文案、商标或产品包装的复制来源。

- 不复制 `fight-the-landlord-main` 中按 GPL-3.0 发布的 Go/Python 包装代码、Docker 文件或素材。
- DouZero 官方源码以 Apache-2.0 为公开来源时，仍需在实际复用前保留许可证、NOTICE 和修改记录。
- 具体 ONNX 权重不能从源码许可证推定授权；必须单独归档来源、许可证、SHA-256 和再分发许可。
- 镜像构建和生产启动不得从公网自动下载模型。

### 隐私与安全

- Sidecar 请求仅包含当前机器人的手牌、公开出牌历史、公开剩余张数和 Node.js 提供的合法候选。
- 不包含账号、昵称、头像、连接信息、钱包、数据库记录或其他玩家真实手牌。
- Sidecar 无状态、无数据库，不持久化请求与特征。
- 模型端口只暴露在 Compose 内部网络。

### 棋牌合规判断

- 本项目属于既有棋牌项目，应按 `chess-fishing-iaa` 类别单独审核，不适用普通 IAA 的“不得包含棋牌玩法”结论。
- 本次改造不新增概率控制、现金、提现、支付、定向邀请、社交或输赢操控能力。
- DouZero 只优化机器人决策，因此必须通过整局灰度、真人胜率与资产指标监控，避免形成暗中控制特定用户输赢的能力。
- 现有项目中的房间邀请、虚拟资产、语音和抽水等存量能力不属于本次改造范围，但与 `docs/game-privacy.md` 的棋牌约束存在明显冲突，正式发布前必须由产品与合规单独评审；本文不将其误报为已合规。

### 概念合规结论

DouZero 技术接入本身可以在“不接触用户隐私、不绕过规则、不控制特定真人结果、不复制未授权代码与权重”的条件下实施。当前项目整体发布合规仍受上述存量棋牌功能和模型权重授权两项门禁约束。
