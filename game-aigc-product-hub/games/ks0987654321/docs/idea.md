## 玩法合同

### 固定规则

1. 游戏为关卡制 PvE，不包含 PVP。
2. 玩家进入关卡前，从当前已解锁的塔防卡牌中主动选择五张，组成当局防御卡组。
3. 卡牌选择为完全可见、可控的确定性选择，不包含随机卡池、概率抽取或保底机制。
4. 进入战斗后只能使用本局选定的五类防御单位。
5. 玩家消耗局内资源，在可建造格部署单位，并对已部署单位进行局内升级。
6. 敌人沿配置中的固定路线移动；抵达终点会扣除基地生命。
7. 清空全部配置波次且基地生命大于零时胜利；基地生命降至零时失败。
8. 关卡结算发放配置指定的局外经验和材料，用于角色局外升级。
9. 卡组中的角色标签可按配置激活羁绊；羁绊只读取配置条件和效果，不写死阵营与职业。
10. 关卡或地图节点按照配置的前置关卡、星数、玩家等级或其他条件解锁。

### 可配置规则

- 战前选卡数量默认是五张，但由 `deckRules.deckSize` 控制。
- 可用角色/塔防卡牌总数由运行时清单的 `cards` 数组长度决定，不固定为六个；选卡界面按单页容量自动分页。
- 题材表现同样配置化：`presentation` 下发主题标识、场景资源、全局配色、角色与敌人色板；缺失时使用包内珊瑚幻想默认题材配置，业务代码不判断具体题材名称。
- 首页标题/副标题/行动文案、地图节点名称与描述、关卡目标、角色卡牌显示名均由运行时配置下发；缺失字段逐项使用完整可读的默认文案。
- 内置兜底语言为简体中文；远程配置仍可替换所有显示文案。
- 完整美术兜底不仅包含配色：`mapStyle` 控制地块、道路、出生点、终点、障碍和背景纹理；`roleAppearances` / `enemyAppearances` 控制体型、头部比例、装备/特征、层级色彩与缩放。图片资源为空或加载失败时按这些参数程序化绘制。
- 是否允许重复卡、必选标签、禁用卡、推荐卡组和免费试用卡均可配置。
- 局内升级上限、成长倍率、费用、攻击、攻速、射程、技能与效果参数均可配置。
- 局外等级、升阶材料、属性成长和技能解锁均可配置。
- 羁绊标签、人数阈值、效果类型、数值与展示文本均可配置。
- 地图节点、路线、格子、障碍、波次、敌人、奖励、资源和主题均可配置。

## 核心循环

`地图选关 → 查看关卡信息 → 从已解锁卡牌中选择五张 → 开始战斗 → 部署/升级/调整防线 → 清理波次 → 结算奖励 → 局外升级或解锁地图 → 下一关`

玩家在战斗中的高频动作：选择卡牌、点击可建造格部署、点击单位升级、清除可配置障碍、观察波次并调整资源分配。

## 战前五卡选择

- 输入：全部已解锁且满足本关限制的塔防卡牌。
- 输出：五个有序或无序卡槽，顺序是否影响战斗栏由配置决定。
- 校验：数量必须满足 `deckSize`；重复、标签、禁用和必选条件必须通过。
- 默认交互：点击卡牌加入/移出卡组，已选区始终显示当前数量，满足条件后才能开始。
- 默认不自动随机补齐；可提供完全确定性的“推荐阵容”，推荐结果来自配置。
- 本地保存最近一次合法卡组；配置版本变化或卡牌失效时重新校验。

## 局内与局外成长

### 局内升级

- 使用基础模板已有的 `levelCap`、`growth`、`upgradeCost`。
- 升级仅在当前对局有效，结算后重置。
- 角色技能参数沿用单位配置中的 `skill`、`skillPower`、`skillDuration` 等字段。
- 点击已部署角色只打开升级面板，不直接扣费；面板显示当前等级、下一次升级花费和可升级状态，玩家点击确认后才扣除局内资源。
- 战前卡牌和战斗底部卡栏都显示该关卡单位配置中的 `buildCost`。

### 局外升级

- 玩家存档只保存角色 ID、等级、经验、突破状态和已解锁状态，不保存题材文案或资源副本。
- 战斗开始时，以关卡下发的基础属性结合局外成长配置生成最终基础值。
- 服务端配置不可用时使用最近一次校验通过的缓存；缓存不可用时使用题材中性的内置兜底配置。
- 关卡列表提供角色升级入口；局外角色卡显示角色形象、等级、购买花费和升级材料花费，点击卡片使用材料升级。
- 局外升级费用由 `progression.baseUpgradeCost` 与 `progression.upgradeCostGrowth` 配置，不在业务逻辑中写死。

## 羁绊系统

- 每张卡牌可配置多个标签。
- 羁绊按战前所选五张卡计算；是否需要实际部署后生效由配置决定。
- 支持属性加成、资源修正、费用修正和技能参数修正等通用效果。
- 羁绊效果必须通过白名单类型解析，禁止远程配置注入可执行代码。
- 多个羁绊的叠加顺序、上限与冲突规则必须确定且可测试。

## 地图与关卡解锁

- 世界地图由节点和有向前置关系组成，不在代码中固化章节数量或节点坐标。
- 每个节点引用一个符合 `schemaVersion: 5`、`fixed-path-v1` 的战斗配置。
- 解锁条件支持前置节点完成、星级、玩家等级和配置标记。
- 地图背景、节点图标、场景资源、格子资源与音频都使用配置 URL 或资源键。

## 基础战斗配置兼容

模板必须原样兼容附件中的基础字段：

- `name`、`revision`、`status`、`delivery`、`schemaVersion`、`template`
- `map`：尺寸、主题、背景、格子、路线、障碍、速度倍率和格子资源
- `units`：数量可变的防御单位及敌人原型、属性、升级、技能、显示和资源字段
- `economy`：初始资源、基地生命、资源回复和上限
- `waves`：波次、分组、敌人引用、数量、延迟和间隔
- `audio`、`waveExecution`、`requiredCapabilities`、`assetManifest`

基础关卡 JSON 不新增必填字段。战前卡组、局外养成、羁绊和世界地图通过独立的运行时配置清单提供，并通过稳定 ID 与 `units` 和关卡配置关联。这样后端可以继续下发原格式关卡数据，模板也能按需装配扩展系统。

## 动态配置策略

1. 拉取运行时清单，读取配置版本、地图索引、卡牌目录、成长规则和羁绊规则。
2. 按地图节点引用拉取基础关卡 JSON。
3. 对 `schemaVersion`、必填字段、引用完整性、数值范围和资源协议进行校验。
4. 校验成功后原子替换内存配置并写入本地缓存。
5. 拉取或校验失败时回退到上一个有效缓存；无缓存时使用中性兜底配置。
6. 配置只包含数据，禁止表达式求值、动态脚本、远程 `eval` 或 Function 构造。

## UI 流程

`启动与配置加载 → 完整关卡列表 → 关卡详情 → 五卡选择 → 战斗 → 胜利/失败结算 → 完整关卡列表`

进入游戏后直接展示 `worldMap.nodes` 下发的全部关卡，不设置客户端关卡数量上限。列表按卡片吸附滚动并只绘制当前视口中的关卡以控制性能；每张卡片显示对应关卡的地图缩略图、编号、名称、描述与锁定状态，点击已解锁关卡进入其详情。

关卡详情页必须提供“返回”按钮，返回完整关卡列表并保留用户此前的滚动位置。

附加入口：卡牌列表、角色局外升级、羁绊说明、设置、隐私政策、用户协议、实名认证、防沉迷和客服。

默认采用竖屏优先、触摸输入和 WebGL 渲染；布局根据安全区及屏幕尺寸自适应。单局时长和画面资源不在代码中固化，由波次数量和配置节奏决定。

前三个入口界面必须形成连续的信息链：主界面展示题材标题与角色群像，世界地图展示当前关卡的真实地图缩略图、节点名和场景描述，关卡详情再次展示地图场景、目标与规则。五卡界面的每张卡必须展示由 `roleAppearances` 驱动的角色形象和配置名称，不能只用色块代替。

- 具体框架、启动命令、健康检查、部署目标与接口契约由 `agw-server-design` 阶段确认。

## 验收条件

- 同一套代码仅替换配置即可加载不同地图、单位、波次、资源和显示文本。
- 开始关卡前必须完成五张合法塔防卡牌选择。
- 战斗中只能部署所选五类单位，并支持局内升级。
- 局外等级、羁绊和地图解锁均由配置驱动且可持久化。
- 附件格式的基础关卡 JSON 可直接通过校验并进入运行时。
- 远程配置失败时能使用缓存或中性兜底配置继续运行。
- 代码中检索不到附件题材名称、单位名称或资源路径常量。
- 不调用任何媒体生成 API。
