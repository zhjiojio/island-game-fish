# 《华君传：翻牌吧女帝》完整游戏设计拆解

> 拆解对象：`https://lineargame.top/h5/index.html?config=ZH&lang=en`
> 完整标题：华君传：翻牌吧女帝｜古风恋爱互动影游
> 拆解方式：GUI 实玩 + PixiJS 场景树遍历 + 全量配置文件直取
> 拆解日期：2026-09-09

## 0. 一句话定性

这是一款 **女尊向·古风宫廷·互动影像游戏（FMV Interactive Story）**，
玩家扮演女帝，在两位男主（华君 / 甄桓）之间做选择，
**核心资源是真人 mp4 视频**，玩法是「看片 → 做选择 / 做小游戏 → 分支走向不同结局」，
变现走 **纯激励视频广告（IAA）**，无内购。

技术栈：PixiJS 全 canvas 渲染（DOM 里只有一个 canvas），横屏 1920×902，HLS/mp4 播放，Firebase + GA 埋点。

配置路径：
```js
cfg = {

  cdnBase: "https://video-1318091918.cos.ap-beijing.myqcloud.com/",  // 腾讯云 COS 北京
```

**关键洞察**：URL 里的 `?config=ZH` 就是切换整个游戏内容包的开关。
换一个 `config` 参数 = 换一整款游戏。
这是一个 **「一套引擎跑 N 款互动剧」的中台化设计**，`ZH` 只是其中一个剧目代号。

### 2.2 节点数据结构

```json
{
  "id": "uuid 或 node_时间戳",
  "title": "节点标题（或本地化 key）",
  "video": "1-1.mp4",
  "thumbnail": "缩略图",
  "question": "抛给玩家的问题文案",
  "choice_style": 5,
  "choices": [
    { "label": "选项文案", "next": "目标节点id", "conditions": [...], "immediate_settle": false }
  ],
  "next": "线性下一节点",
  "qte": { ...小游戏配置... },
  "statEffectConfigs":      { "suspect": { "value": 2 } },
  "characterEffectConfigs": { "huajun": { "favor": { "value": 2 } } },
  "nodeType": "end",
  "is_end": true,
  "end_type": "death | chapter | game",
  "death_desc": "死亡结局说明",
  "game_desc": "通关结局说明",
  "end_bg_url": "结局背景图",
  "duration": 5,                  // 限时选择（秒）
  "default_choice_index": 2,      // 超时默认选项
  "auto_select_by_condition": true // 按条件自动选路
}
```

### 2.3 三种结局类型（分层设计，很关键）

| end_type | 含义 | 数量 | 作用 |
|---|---|---|---|
| `death` | 即死结局（Bad End，选错就完） | 12 | 制造紧张感 + 逼玩家回溯重玩 |
| `chapter` | 章节通关 | 5 | 正常推进 + 触发广告解锁下一章 |
| `game` | 全局真结局 | 4 | 最终收束（华君HE/BE、甄桓HE/BE） |

**设计意图**：12 个即死结局 vs 4 个真结局。
死亡率极高，这是刻意的——**死亡是内容消耗的放大器**，
玩家为看完整内容必须反复回溯，从而反复看广告、拉长生命周期。

第 3 章最狠：15 个节点里塞了 **6 个结局，其中 5 个是即死**。几乎每一步都能死。

### 2.4 分支拓扑

典型 **菱形收束结构（Diamond Convergence）**：

```
起点 → 分叉(2~3路) → 各自演出 → 收束回主干 → 再分叉 → ... → 终局分叉
```

好处：**分支体验 + 可控成本**。玩家感觉选择很多，但视频资产复用率高。
第 6 章的 4 个结局前面都汇聚到同一个「朝局落定」过渡节点，然后才分四路，
甚至「朝局落定」这个节点复用了同一个视频 `cab.mp4` 四次 —— 极致的资产复用。

## 3. 核心玩法：QTE 微游戏系统（最大亮点）

**14 处 QTE，9 种类型。** 这是它区别于普通「点选式互动剧」的关键。

| 类型 | 次数 | 玩法 | 出现位置 |
|---|---|---|---|
| `sceneclickvideo` | 4 | **场景点击探索**：在一张背景图/视频上有多个热点，点击各自播放一段小视频，达到阈值才通关 | 1-5、4-5、5-3、b-5 |
| `swipeerase` | 2 | **滑动擦除**：在指定区域按方向滑动 N 次（擦拭/揭开） | 1-10、4-7 |
| `click` | 2 | **连点/长按**：指定区域点 N 次（如「女帝打虎」点 7 次、「策马追赶」点 4 次） | 5-4b、a-1 |
| `imperial_seal` | 1 | **拟诏盖印**：填空式诏书，玩家为两位男主选择位份（三阶常侍/四阶侍君），再盖玉玺 | 1-3 |
| `longpress` | 1 | **长按**：按住指定区域 press_time 秒 | 1-10qte |
| `lantern_release` | 1 | **放河灯**：选祈愿文案（每条有 score），放灯 | 2-5 |
| `puzzle` | 1 | **拼图**：3×3 九宫格拼图 | 2-9 |
| `paper_cutting` | 1 | **剪纸描摹**：沿虚线描摹轮廓，回到起点自动闭合，按精度判定成败 | 2-14 |
| `mask_choice` | 1 | **面具选择**：选傩戏面具（镇煞/破邪/…），每个对应不同视频分支 | 4-1 |

### 3.1 QTE 通用参数（引擎级设计）

```json
{
  "type": "swipeerase",
  "duration": 6,                          // QTE 时限
  "delay_from_start_seconds": 1,          // 视频播到第几秒才触发 QTE ★
  "area_position": "0.446,0.771",         // 归一化坐标（适配任意分辨率）★
  "area_size": "0.3,0.3",
  "next_node_map": { "0": "失败节点id", "1": "成功节点id" },  // 成败分流 ★
  "instruction_text_1": "引导文案"
}
```

**三个精妙设计点**：

1. **`delay_from_start_seconds`** —— QTE 不是独立关卡，而是**叠加在视频播放时间轴上的**。
   例：第 1 章 `imperial_seal` 在视频第 **201.43 秒** 触发；第 4 章 swipeerase 在第 **185 秒** 触发。
   这意味着玩家在看片时会被突然打断要求操作，**沉浸感 + 紧张感极强**，这是 FMV 互动剧的正确做法。

2. **归一化坐标** `0.446,0.771` —— 全部用 0~1 相对坐标，一套配置适配所有屏幕。

3. **`next_node_map` 成败分流** —— QTE 成败直接改变剧情走向。
   例：第 5 章「女帝打虎」点 7 次，失败 → `打虎失败`（即死结局），成功 → `打虎成功` → 继续。
   **QTE 不是装饰，是真实的死亡判定器。**

### 3.2 限时选择

第 5 章开场：`duration: 5, default_choice_index: 2`
→ 5 秒内不选，自动走第 3 个选项「谁也不抓」。
经典的「犹豫也是一种选择」设计。

### 3.3 场景点击探索的细节

```json
"scene_click_video": {
  "background": "yeshou.mp4",        // 背景可以是视频，不只是图
  "completionThreshold": 2,          // 点满 2 个才算完成
  "points": [
    { "id":"point_1", "x":0.51, "y":0.728, "arrowDir":8,
      "label":"躁而不攻", "video":"5-3a.mp4",
      "allowSkip":true, "replayable":true }
  ]
}
```

`arrowDir` 是引导箭头方向，`replayable` 允许重看，`completionThreshold` 控制「看几个就够」——
**给了玩家探索自由度，同时保证推进节奏**。

## 4. 数值系统

### 4.1 两个数值

```json
statConfigs: [
  { "id":"favor",   "displayName":"羁绊值", "initialValue":0, "showToast":false, "perCharacter":true },
  { "id":"suspect", "displayName":"疑心值", "initialValue":0, "showToast":true,  "perCharacter":false }
]
```

| 数值 | 范围 | 特性 | 设计意图 |
|---|---|---|---|
| **羁绊值 favor** | 0-100 / 每角色独立 | `perCharacter: true`、`showToast: false`（**加了不提示**） | 暗数值，玩家不知道具体加了多少 → 制造不确定性 + 重玩动机 |
| **疑心值 suspect** | 全局单一 | `showToast: true`（**加了会弹提示**） | 明数值，作为可感知的危险警报 |

**这个明暗搭配非常老练**：
- 好感悄悄涨（你不知道自己讨好得够不够 → 焦虑 → 重玩）
- 疑心明着涨（你知道自己在踩雷 → 紧张 → 谨慎）

### 4.2 羁绊值发放（全 21 处 characterEffectConfigs）

单次加值档位只有 **+2 / +3 / +4 / +8** 四档：

- `+2`：普通讨好（占多数）
- `+3` / `+4`：关键选择、独占性选择（如「先赐华君狐裘」+4 vs「先问甄父旧疾」+4）
- `+8`：**终章「救谁」的排他性选择**（华君救援 +8 / 甄桓救援 +8）

注意第 1 章 `1-4b-zh.mp4` 给 zhenhuan **+4**，而 `1-4c-same.mp4` 只给 **+2** —— 独占互动比群体互动值钱。

### 4.3 关系阶段（三段式）

```json
relationshipUnlockFavor: 20   // 20 才解锁「关系」概念
relationshipStages: [
  { minFavor: 20, relationship: "阶段1" },
  { minFavor: 50, relationship: "阶段2" },
  { minFavor: 80, relationship: "阶段3" }
]
```

阶梯 **20 / 50 / 80**（间距 30、30），配合单次 +2~+4 的发放速率
→ 达到 80 需要约 20~30 次正确互动 → **必须玩通全部 6 章且专攻一人**。
这就自然形成了「一周目只能攻一个人」的设计，**双男主 = 双倍重玩需求**。

### 4.4 结局判定逻辑（最关键的发现）

终章「烽烟未歇」节点：

```json
{
  "auto_select_by_condition": true,
  "choices": [
    { "label":"华君救援", "conditions":[
        { "condition_type":1003, "character_name":"huajun", "other_character_name":"zhenhuan" }]},
    { "label":"甄桓救援", "conditions":[
        { "condition_type":1003, "character_name":"zhenhuan", "other_character_name":"huajun" }]}
  ]
}
```

`condition_type: 1003` = **比较两个角色的羁绊值高低**。

即：**终章救谁不是玩家选的，是系统根据你前 5 章累积的好感自动判定的。**
`auto_select_by_condition: true` 让这个节点自动选路。

这是全局最精妙的一处设计：
- 玩家以为自己在做无数个小选择
- 实际上系统在暗中累加两条好感线
- 终章直接告诉你「你的心已经选好了」

然后 HE / BE 的分岔在后续「亡命途中 → 竹影藏锋 → 临行托付」三个选择点，
每个都是 2 选 1（顺着他说/故意打趣、由心而行/不失本心、信其决断/借势甄家），
最终收束到 4 个 `game` 结局。

**完整结局矩阵**：

| 结局 | 视频 | 前置 |
|---|---|---|
| 华君 HE | `hjHE.mp4` | huajun favor > zhenhuan + 后续选择正确 |
| 华君 BE | `hjBE.mp4` | huajun favor > zhenhuan + 后续选择错误 |
| 甄桓 HE | `zhHE.mp4` | zhenhuan favor > huajun + 后续选择正确 |
| 甄桓 BE | `zhBE.mp4` | zhenhuan favor > huajun + 后续选择错误 |

## 5. 角色系统

### 5.1 双男主设定（教科书级的差异化）

| | 华君 huajun | 甄桓 zhenhuan |
|---|---|---|
| 定位 | 明艳张扬 · 傲慢嘴毒 · 争宠直白的「小娇夫」 | 温柔无害 · 白切黑 · 擅长示弱的「绿茶小狗」 |
| 出身 | 镇北大将军之子，家族显赫有底气 | 大理寺卿之子 |
| 外傲内娇点 | 越在意越嘴硬、越害怕越攻击 | 越会演、越不敢真 |
| 核心恐惧 | 怕女帝选他只因华家，不因他本人 | 曾因真心被利用受伤，不敢先暴露真心 |
| 宣舞人设 | 鎏金夜宴 · 近侍｜张扬，勾人，会撩 | 月下清庭 · 司乐｜清冷，克制，含蓄 |
| 徽章 | 馆内人气第一！ | 馆内新宠登席！ |

**两人是完美互补的原型**：明攻 vs 暗攻、直球 vs 心机、张扬 vs 克制。
覆盖了女性向内容里最主流的两种男主偏好，**用最小角色数吃最大受众面**。

### 5.2 皮肤系统（与剧情进度绑定）

每人 3 套皮肤：

```
skin_1: 默认（无解锁条件）
skin_2: unlockChapterID=2, unlockNodeID=62abc632...
skin_3: unlockChapterID=3, unlockNodeID=d51c1b5c...
```

**皮肤不卖钱，靠推剧情解锁** —— 这是内容型产品的正确选择：
用外观奖励驱动内容消耗，而内容消耗驱动广告曝光。

### 5.3 AI 角色扮演系统（隐藏的重头戏）

每个角色配了一份 **完整的 LLM 人格 Prompt**（华君 574 字、甄桓 611 字），结构为：

1. **身份锚定**：「你将扮演角色「华君」——女帝身边的男子」
2. **玩家关系定义**：「玩家是女帝，是你侍奉、试探、争夺、依附与动心的对象」
3. **性格描写**：明艳/骄矜/占有欲…（含反差要求：「不要只写跋扈，要写出他越在意越嘴硬」）
4. **口吻锁定**：称玩家为「陛下」或「四娘」
5. **输出格式约束**：
   > 每次玩家发言后，请给出情绪变化并给出当前情绪状态，必须是以下之一：
   > `idle`（平静默认）/ `happy`（开心振奋）/ `angry` / `sad` / `lovely`

**情绪 → 视频映射**：

```json
personaEmotion: {
  hello:  "huajun_hello.mp4",
  idle:   "huajun_idle.mp4",
  happy:  "huajun_happy.mp4",
  angry:  "huajun_angry.mp4",
  sad:    "huajun_sad.mp4",
  lovely: "huajun_lovely.mp4"
}
```

**这是整个产品最有前瞻性的设计**：
LLM 返回情绪标签 → 前端切换对应的真人情绪视频 → **实现「有表情反应的 AI 男友」**。
只需 6 段视频，就能撑起无限轮次的动态对话。

配套：`quickTalks` 快捷语按钮（每人 2 条预设话术，降低开口门槛）。
加载的 JS 里也能看到 `aiGateway.js`、`viduLive.js` —— AI 网关 + 实时数字人能力。

**当前状态**：角色档案页羁绊 0/100 时角色卡不可点击（`eventMode: passive`），
**AI 聊天必须羁绊 ≥ 20 才解锁** —— 用 AI 陪聊作为数值系统的终极奖励。

## 6. 宣舞系统（第二增长曲线）

这是一个**与主线剧情完全解耦的独立变现模块**，本质是「短视频舞蹈点播馆」。

### 6.1 结构

```
宣舞 → 选角色（华君/甄桓）→ 舞蹈馆 → 双 tab（随心看 / 解锁看）→ 8 支舞/人
```

总量：**2 角色 × 8 支 = 16 支舞**，其中免费 8 支、广告解锁 8 支（精确 1:1）。

### 6.2 分配策略（编号交错）

| 免费（随心看） | 广告解锁（解锁看） |
|---|---|
| 03 回廊律动舞 | 01 雪夜舞 |
| 04 灯火庆典舞 | 02 一根红绳 |
| 06 KK Drop舞 | 05 月下超Chill舞 |
| 07 喵喵拳 | 08 宫宴邀舞 |

**编号故意交错（01锁/03免/05锁/07免）**，而不是「前 4 免费后 4 收费」。
效果：玩家在网格里浏览时，锁与不锁交替出现，**每一屏都有付费诱饵**。

另一个细节：免费的舞偏「潮流网感」（KK Drop舞、喵喵拳、超丝滑手势舞、左右鬼步舞），
付费的舞偏「情绪暧昧」（雪夜舞、一根红绳、月下超Chill舞、宫宴邀舞）。
**免费的负责拉新和传播，付费的负责卖情绪。**

### 6.3 试看机制（实测验证）

| | 免费舞 | 锁定舞 |
|---|---|---|
| 弹窗标签 | 观看权益：**不限次** ／ 解锁方式：随心看 | 试看权益：**5秒** ／ 解锁方式：看广告 |
| 按钮 | 「观看此舞」 | 「**看广告解锁**」 |
| 实测播放 | 播到 13.5s 无中断，结尾自动 **loop 循环** | 5 秒截断 |

实测数据（免费舞 huajun03.mp4）：
`currentTime = 1.58 → 3.58 → 5.59 → 7.59 → 9.58 → 11.58 → 13.56 → 0.76 → 2.75 → 4.76`，`paused` 全程 `false`。
**证实免费舞完整无限循环，5 秒限制只作用于锁定舞。**

### 6.4 文案设计（沉浸式包装）

它没有用「解锁」「购买」这类工具化词汇，而是全部改写成古风叙事：

> 「今夜，陛下想宣谁献舞？择一人入席，先垂览五息；若心意已定，看一段广告便可留住这一支舞。」
> 「可先试看 5 秒；看完一段广告，这一支舞便永久收入陛下的**舞册**。」
> 「每支舞均可先试看五息，解锁后可无限回看；私藏限定将标注观赏期限。」

- 「5 秒」→「五息」
- 「解锁永久拥有」→「永久收入陛下的舞册」
- 「选择角色」→「宣谁献舞 / 择一人入席」

**把广告变现包装成帝王赏舞的权力快感**，这是文案层面的高级操作。

## 7. 变现设计（纯 IAA，零内购）

### 7.1 三个广告位

| 广告位 | 触发点 | 数量 | 性质 |
|---|---|---|---|
| **章节解锁** | 每章开始前 | 1+1+1+2+2 = **7 次** | 强制（主线必经） |
| **舞蹈解锁** | 宣舞锁定舞 | **8 次** | 自愿（内容付费） |
| **章节内广告** | `chapterAdPending` 字段 | 不定 | 流程内插播 |

### 7.2 章节广告梯度（递增式设计）

```
第1章: 0 次 ← 免费白嫖，先勾住
第2章: 1 次
第3章: 1 次
第4章: 1 次
第5章: 2 次 ← 后期加码
第6章: 2 次 ← 终章最贵
```

**经典的「先免费上钩，越到高潮越收费」曲线。**
第 1 章 0 广告让玩家零摩擦体验完整玩法（含 4 个 QTE + 分支 + 即死结局），
建立沉浸后才开始收费，而到了最想看结局的终章要看 2 次广告。

### 7.3 一周目总广告量估算

```
主线 7 次（章节解锁）
+ 死亡回溯重看（12 个即死结局，保守估计触发 5~8 次回溯）
+ 舞蹈解锁 8 次（自愿）
≈ 单个深度玩家 20+ 次激励视频曝光
```

再叠加「双男主 = 至少 2 周目」「HE/BE 各 4 结局 = 想集全要 4 周目」，
**LTV 可以拉到 50+ 次广告曝光**。

### 7.4 隐藏的完整运营中台（UI 未开放）

从 `xuanwu` 对象的方法列表能看到大量**已实现但当前 UI 未暴露**的功能：

```js
// 货币系统
wallet: getCoins, addCoins, spendCoins
xuanwu: getCoins, canAfford

// 解锁系统
unlockDance, unlockDanceFree, isUnlocked, getUnlockExpiresAt  // ← 限时解锁

// 签到系统

isDailyLoginClaimed, claimDailyLogin

// 任务系统

// UGC 心愿墙

// AI 生图

isPortraitFirstFreeAvailable   // ← 首次免费生图
```

**这说明产品的完整规划远大于当前上线版本**：
- `getUnlockExpiresAt` 印证了「私藏限定将标注观赏期限」的**限时解锁**设计
- `wallet + canAfford` 是**虚拟币经济**（看广告赚币 → 币解锁舞，而非一舞一广告）
- `submitWish / likeWish` 是**心愿墙 UGC**，让玩家投票决定下一支舞/下一章内容
- `generatePortrait` 是 **AI 生成角色写真**（首次免费，后续付费/看广告）
- 签到 + 任务 + 红点 = **完整的日活留存框架**

当前版本只放出了最简单的「一舞一广告」，把复杂系统藏在后面分批开放。

```js
    characters: { huajun: {}, zhenhuan: {} },
```

- `version: 2` + `legacyKeys` = 做过存档迁移，产品已有一定运营时长
- 单存档位（`slotCount: 1`）—— 简化设计，但意味着无法并行多周目

「官方群」放在主菜单常驻位 —— **私域导流优先级极高**。

## 10. 可复用的设计方法论（12 条）

给要做同类产品的人：

1. **引擎与内容彻底分离**：`?config=XX` 换整个剧目。一套播放器跑 N 款互动剧，这是规模化的唯一路径。

2. **QTE 挂在视频时间轴上**（`delay_from_start_seconds`）而非独立关卡。让操作打断沉浸，制造真实的临场感。

3. **QTE 成败直接分流剧情**（`next_node_map`）。小游戏不是装饰，必须能杀死玩家，否则玩家不会认真做。

4. **归一化坐标**（0~1）做所有热区，一套配置适配全分辨率。

5. **明暗双数值**：好感暗涨（不提示，制造焦虑与重玩），危险明涨（弹提示，制造紧张与谨慎）。

6. **即死结局当内容放大器**：12 个 death vs 4 个真结局。死亡逼回溯，回溯拉长生命周期和广告曝光。

7. **菱形收束拓扑**：分叉 → 演出 → 汇合 → 再分叉。给分支体感，控制资产成本。终章甚至一个过渡视频复用 4 次。

8. **终局按累积数值自动判定**（`condition_type: 1003` 比较双方好感）。玩家以为在做小选择，系统在暗中记账，最后告诉你「你的心早已选好」——这是互动剧最高级的叙事技巧。

9. **双男主用互补原型**：明攻/暗攻、直球/心机。最小角色数吃最大受众面，且天然产生 2 倍重玩。

10. **LLM 情绪标签驱动真人视频**：强制 AI 输出 `idle/happy/angry/sad/lovely`，映射到 6 段视频。用极小的素材量撑起无限轮对话，这是 AIGC 时代的关键杠杆。

11. **广告梯度递增**：首章 0 广告白嫖，越接近高潮越贵（终章 2 次）。先给完整甜头，再收费。

12. **变现文案全部叙事化**：「解锁」→「收入陛下的舞册」，「5 秒」→「五息」，「选角色」→「宣谁献舞」。把付费动作包装成角色扮演的一部分。
