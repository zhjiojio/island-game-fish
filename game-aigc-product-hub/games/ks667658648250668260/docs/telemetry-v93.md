## v92.6 免广告通行证全局生效修复

「解锁全部章节」看满 3 个激励视频后，当天应全局免广告。此前 `adPassActive()` 判定被手写在 `choose()`（选项广告）与 `chapter-home.unlock()`（章节解锁）两处，而全局共有 5 个激励视频调起点，另外三处完全没查通行证：BE/大结局页「看广告复活重选」、节点级 `node.ad` 拦截、成就「看广告直通该章」。用户在大结局页仍被弹广告即由此产生。

本版收敛为单一真值源 `showRewardedGated(onOk, onFail, slot)`：内部先查通行证，命中则零延迟直接发奖、不调起 native 广告。除通行证记账入口 `doUnlockAllAd` 外，禁止任何位置再直接调 `KwaiAd.showRewarded`。

| 事件键 | SceneID | 含义 |
|---|---:|---|
| `ad_pass_skip` | 11676 | 通行证生效、跳过一次激励视频 |

维度 `ad_slot` 区分被免掉的广告位：`choice_unlock` / `node_ad` / `be_revive` / `achievement_direct`（章节解锁走 chapter-home 的既有 `chapter_ad_*` 口径，不重复计），另带 `node_id` / `chapter_id`。核对方式：同一 boot 内出现 `ad_pass_skip` 后，不应再出现任何 `*_ad_request` 或广告成功事件；若仍出现即说明有新增调起点绕过了闸门。该键每次启动去重，是 UV 口径，不能用来数被免掉的广告次数，只能判定「特权是否生效」。

同时收紧末帧兜底：`position` 逼近片尾且连续停滞 ≥600ms **且** 停滞采样数 ≥2 才判定 `onEnded` 失效，避免正常播放的最后一帧被提前掐断（表现为视频最后一秒被截断、选项提前弹出）。此前的 `duration - 0.35s` + 2 次命中窗口过宽，快手 250ms～1s 的采样密度下几乎每支视频都会误命中。

## v92.5 视频内互动「拖拽解锁」漏斗

op1 视频播到 `pauseAt=10.0s` 暂停并弹出拖拽引导层，玩家必须沿弧线把手势从衣领拖到右肩才继续播放。新增四个全局事件键（不带节点后缀，按 `node_id` 维度区分场景），每次启动去重 = UV 口径：

| 事件键 | SceneID | 含义 | 漏斗位置 |
|---|---:|---|---|
| `drag_unlock_arm` | 11672 | 视频到达 pauseAt、引导层可见 | 分母 |
| `drag_unlock_try` | 11673 | 手指按在起点、真正进入拖拽 | 意图 |
| `drag_unlock_fail` | 11674 | 抬手未通过三重校验，可重试 | 流失原因 |
| `drag_unlock_ok` | 11675 | 校验通过、撒花并恢复播放 | 分子 |

同时补登此前未入册的节点/选项键：`f_op1_outfit`（node_view 11662、first_choice 11663、first_commit 11664、两个选项 11665–11670）、`s_op1_lace`（node_view 11671）。

## 1. 四个业务问题如何计算

| 指标 | 分子 | 分母 | 用途 |
|---|---|---|---|
| 首页章节选择率 | 看见该卡片且点击该卡片的用户数 | 看见该卡片的用户数 | 判断封面与标题吸引力 |
| 章节进入转化率 | 点击该卡片且真正开始显示本章内容的用户数 | 点击该卡片的用户数 | 判断解锁/加载流失 |
| 页面/节点到达率 | 同期到达该页面/节点的用户数 | 同期启动用户数，或本章内容到达用户数 | 定位剧情流失，必须注明分母 |
| 选项点击率 | 曝光且点击该选项的用户数 | 曝光该选项的用户数 | 判断选项吸引力；每个选项独立分母 |
| 首次选择分布 | 某选项作为节点首次点击的启动数 | 该节点发生过首次点击的启动数 | 互斥分叉占比，合计 100% |
| 选项执行转化率 | 点击后实际执行该分支的用户数 | 点击该选项的用户数 | 区分广告意图、未看完和真正进入 |
| 章节人均有效停留 | 按用户汇总本章前台剧情时长后求和 | 本章内容到达用户数 | 展示已采集时长均值，同时展示覆盖率 |

“用户”优先用平台数仓可用的稳定账号标识；只有 device_id 时应在看板标为设备 UV，不能称为跨设备账号人数。代码不上传登录 code、昵称或原始 openid。会话级用 `boot_id`，每天同一用户可以有多个启动。

一个节点先选 A、重玩后选 B，两个 option_click 都会有数据；所以各选项点击率之和可以大于 100%。只有 `node_first_choice` 是每启动、每节点互斥首选。跨启动求“用户首次选择”还必须按用户+节点排序，只取第一条，不能把各选项 UV 相加作为互斥分布。

## 2. Scene 通道与去重

同一 SceneID 每次真实进程启动最多占用一次。进入章节、重玩、回首页、清存档、退后台再回来，都不会重置 boot_id 或已上报集合。真正重新加载小游戏才建立新 boot_id。

发送状态分为 pending / acknowledged / failed。成功回调只说明 SDK 已确认，不等于已验证数仓入库；返回 true 仅代表已调用 API。收到明确 fail、抛异常或明确未调用成功，最多再尝试一次，使用第一次事件的相同维度；无回调保持 pending，不盲目重发。失败诊断独立 Scene。平台仍可能拒绝重复 ID，因此重试不是可靠投递保证。

不把 reportAnalytics 当作备用通道。`Telemetry.track` 仅在 DEBUG_CONSOLE 打开时输出调试信息；历史其他文件中的 Analytics 调用不属于本规范有效数据源。

## 3. 字段定义

| 字段 | 位置 | 含义 |
|---|---|---|
| v | dimension | 埋点协议 v93.0.0 |
| game_version | dimension | 游戏及剧情数据版本 v92.6；字典须同版本关联 |
| boot_id | dimension | 从模块加载到进程销毁的唯一启动标识 |
| event_key | dimension | 新埋点语义键，例如 card_click:EP02；旧里程碑用 scene_id 查询 |
| chapter_id | dimension | 玩家所在章节；卡片/解锁/转场事件为目标章节 |
| content_ep | dimension | 节点在剧情文件中的原始 EP；公共失败节点可能为 EP99 |
| node_id / node_type | dimension | 节点固定 ID / 节点类型 |
| option_id | dimension | 固定选项 ID，重排不变；文本/目标见同版本 CSV 字典 |
| opt_idx | dimension | 当前版本按钮位置，仅供定位，不作为稳定身份 |
| entry_source | dimension | 最近进入来源：chapter_home / transition / resume 等；不代表平台投放来源 |
| locked | dimension | 首次卡片曝光或首次点击时的锁定状态，1/0；后续状态改变不重报该 ID |
| configured_ad | dimension | 选项配置是否带广告，1/0 |
| requires_ad | dimension | 当前此动作是否还需广告，排除已解锁及管理员跳过 |
| admin_bypass | dimension | 该事件是否处于已验证管理员跳过广告状态，1/0；不是所有管理员的身份标记 |
| source / from_chapter | dimension | 章节解锁来源 / 转场上一章 |
| reason | dimension | 计时刷新原因或广告失败原因 |
| delta_ms / seq | metric | 本次新增有效毫秒 / 启动内时长片序号 |
| costTime | 顶层 | 事件距离启动的耗时毫秒，不可代替章节停留时长 |

dimension 值为非空字符串，metric 值为数字字符串；各自序列化控制在 1000 UTF-8 字节以内。标题、按钮文案通过字典关联，避免长文本挤掉身份字段。SDK 未就绪或未开通的设备不保证有数据；看板应同时关注平台版本和启动样本覆盖。

## 4. 触发与可见性

### 首页和章节

- `page_view:chapter_home`：章节首页真正绘制且未被隐私/广告等遮挡。
- `card_view:EPxx`：卡片至少一半高度在列表视口内，未被隐私或广告遮挡；只在首个合格绘制帧记录。不要求停留 300ms，也不等封面下载成功；衡量包含标题和按钮的卡片展示。
- `card_click:EPxx`：用户选择卡片，早于请求解锁广告或进入。曝光与点击事件都是每启动该卡片一次。
- `chapter_ad_request/ok/fail:EPxx`：只有需要解锁时触发。已解锁章不会凭空产生成功事件。管理员跳过的事件带 admin_bypass=1，分析广告时排除。
- `chapter_enter:EPxx`：通过权限检查并切换到章节流程，资源可能仍在加载。
- `chapter_ready:EPxx`：本章第一份有效内容可见，作为章节内容到达及人均时长的分母。
- `chapter_complete:EPxx`：抵达后续章节边界，或正常大结局已绘制。失败结局不会计通关。
- `preview_view:目标章`：章节过渡页曝光；`preview_next/replay/home:目标章` 对应三种操作，from_chapter 记录刚完成章节。最后一章没有下一章预告，不应期望 EP01 的预告出现。

卡片点击不是全渠道章节进入的前置条件：连续剧情从转场进入下一章没有首页卡片点击。渠道漏斗要按来源拆开，不能强行用全部 chapter_ready 除以首页点击。

### 剧情、页面与选项

- 为当前 252 个在册节点建立 `node_view` 字典（EP06–EP09 下架后其键已退役，不作分母）。图片正文只在目标图片加载成功后计到达；视频需已开始且非加载状态。引擎自动跳过且没有实际展示的旁白节点自然没有曝光，这不是漏接。
- choice 的标题和按钮已绘制即可计节点到达，背景图等待/失败不妨碍用户做选择。每个 `option_view` 还单独验证对应按钮命中区至少一半在屏幕内。
- 教学、隐私、成就抽屉/详情/弹卡、章节面板和广告遮挡时不计底层节点及选项曝光。暂停播放按钮不使已经可见的内容消失，但暂停时不计有效时长。
- `option_click`：用户点击意图；`node_first_choice` 同时锁定本启动这个节点首次点的是哪个选项。
- `option_commit`：广告门槛已通过，进入实际应用分支逻辑之前；`node_first_commit` 锁定首次执行的选项。这不是“下一段视频成功起播”，后者看目标节点的 node_view。
- 广告取消只有点击，不能有 commit。奖励回调内部递归不再作为用户新点击。
- 页面类型包含首页、剧情、choice、BE、正常结局、章节面板、教学、隐私、成就和章节过渡页。通用页面 ID 只表示首次到达该页面类型；逐节点分析使用 node_view。

## 5. 有效时长：有边界的增量统计

计时归属始终是当前游玩章节 chapter_id，不把 EP99 公共失败内容当作第 99 章。仅累计前台可见的剧情/选项交互时间；扣除后台、广告请求与播放、首页、章节过渡、隐私/教学/成就/章节面板、暂停播放、纯图片/视频加载等待，以及 BE/结局停留。

模块在启动时绑定生命周期。先结算旧时间区间，再切换章节/状态；onHide 结算当前区间，onShow 重新设基线，等下一帧确认可玩后恢复计时。章节切换、提交选项、停止媒体和前后台切换及时发送；连续可玩时约每 30 秒发送。心跳与渲染共享同一基线，避免重复累加。管理员跳过状态变化也分片。

采用固定 **256 个时长 SceneID（20000–20255）**。每条只含该片新增的 delta_ms，不发送累计值；按 boot_id+scene_id 去重后求和。同一次启动不重用时长 ID。用尽后停止新增时长，发送 duration_exhausted；后台须标记该启动时长不完整。256 不是分钟数：频繁切换会更早耗尽，连续播放理论最多约 128 分钟，需实测槽位耗尽率。

边界必须展示：

1. 强杀可能丢失最后约 30 秒尾段（正常计时、正常投递情况下）；SDK失败或网络故障可能损失更多。没有 onHide 就无法保证最终汇总送达。
2. 有章节到达却没有时长行，可能是快速离开，也可能是投递损失；不能只统计有时长的人来抬高平均值。
3. 报表输出“已采集有效时长/到达用户”，同时输出有时长覆盖率、时长槽位耗尽率与上报失败样本。它是观测值，不宣称无损真实停留。
4. 30 秒分片按上报日归档。跨午夜未拆分区间，按自然日精确分摊需另行设计，当前是上报日期口径。
5. 仅 reportScene 无法提供无限次 PV、精确全量按钮次数或无限时长；若后续开通事件流通道再扩展，不能用重置去重标记伪造支持。

- 固定 option_id 已写入剧情源。重排携带原 ID；新增选项用新 ID；业务含义改变的新分支也应分配新 ID。不要通过改旧 ID 指向不同含义“省号”。
- `make build` 同步构建 manifest 与 CSV。未登记的新事件会令构建失败；先检查业务含义再运行 `node scripts/tools/build-telemetry.cjs --allocate` 追加编号。退役键禁止复活；SceneID 唯一性和选项 ID 唯一性均受校验。

旧数据只能描述各旧版本当时的槽位。v93 开始固定选项身份，不可据此假定历史各版本的 optIdx 从未改变。维度升级后 SQL 使用 snake_case 字段；旧 ep/nodeId/hasAd 字段不能直接混查。

## 7. 验证和上线检查

- `make build`、`make test-telemetry`：验证字典、去重、计时、曝光、失败重试与字段大小。
- 引擎浏览器回归：320/393 两种宽度；首页卡片可见与点击、八次章节边界、取消/重试/迟到奖励、奖励幂等、当前章重玩，以及 option_view/click/commit 真实接线。
- 默认 TELEMETRY enabled；DEBUG_OVERLAY=false，DEBUG_CONSOLE=false。可执行 `Telemetry.diagnostics()` 查看本机启动、时长槽位和发送状态。
- 真机扫码完成一次“首页→免费第一章→奖励支线取消/成功→第二章解锁→切后台再返回”，在 CUSTOMIZE_SCENE 验证同一个 boot_id 和下面字典的事件链。
- v92 用户曾实测 9xxx 无预注册即可成功；v93 新号段尚需后台核验，不能仅凭 mock SUCCESS 宣布已入库。也需核验设备最低版本、平台报送频控和负载。
- 上报失败后不要把空数据解释成真实零转化。出现成片事件缺失，先看平台采集状态和 diagnostics，再分析产品流失。
