## 一、玩法拆解（截图能证明的部分）

### 1.1 核心循环（纯净玩法页是最强证据）

纯净玩法页里有一个之前被弹窗挡住的关键细节：**两辆青色车已在车位上，车顶开着门，车上方有一列青色豆子正排队往下走**（21 号车上方一条竖列，5 号车上方一小撮）。

```
① 从底部候选区拖一辆车 → 落进 6 车位之一
② 车门向两侧张开（装载态开启）
③ 图案上同色豆子「自己走路」离阵 → 排成一列 → 钻进车门
④ 每进一颗，车顶数字 −1
⑤ 数字归零 → 关门 → 倒车 → 转向 → 驶出屏幕 → 空出车位
⑥ 图案全清 → 过关
```

**这条「豆子自己走路排队」是竞品的灵魂**，也是它区别于普通消除的地方 —— 玩家不是"点掉方块"，而是"指挥一群小人搬家"。我方 `pd-game.js` 的 `spawnWalk` / `flights` 已实现同构逻辑，这一点没做错。

### 1.2 失败与复活（新增图给出的完整链路）

```
死局判定（6 车位被装不满的僵尸车占死）
   ↓
【复活弹窗】"复活并消除前 3 辆汽车" → 🎬获得
   ↓ 用户拒绝（点右上红 X）
【失败页】ribbon 你失败了 + 哭脸 + 别放弃，胜利就在前方！
   ↓
[主页]  [再试一次]  [分享]
```

**两层漏斗的设计意图非常明确**：
- 第一层（复活弹窗）= **变现层**，唯一 CTA 是绿色看广告按钮，关闭按钮做得小且在框外
- 第二层（失败页）= **留存层**，主 CTA 变成绿色「再试一次」，用情绪化哭脸 + 鼓励文案降低流失

对比我方现状：`pd-game.js` 的 `phase==='dead'` 是**一次性把 3 个广告选项平铺**（revive / expand / tow），没有分层。竞品的做法转化率更高 —— 一次只给一个决定。

### 1.3 变现点位（6 个，全部用户主动触发）

| 点位 | 位置 | 竞品形态 |
|---|---|---|
| 速度×2 | 车位行下方**独占一行**，左侧，小尺寸低调 | `⏩▶ 速度x2` 白色小卡 |
| 第 6 车位解锁 | 车位行最右 | 深灰圆角块 + `🎬解锁` |
| 升级 | 底部左 | 黄圆按钮 + 红 `+` 角标 |
| 消除 | 底部中 | 黄圆按钮 + 红 `+` 角标 |
| 刷新 | 底部右 | 蓝圆按钮 + 红 `+` 角标 |
| 复活 | 死局弹窗 | 绿 pill + 🎬 |

**注意角标语义**：竞品三个道具用的是**红底白 `+`**（"加/补充"），不是 `▶`。播放图标只出现在「解锁」「速度」「复活」这类纯广告位。我方现在全部用 `▶` 绿标 —— 语义混淆，且绿色角标和绿色 CTA 抢注意力。

## 二、UI 风格：Casual Candy 3D（可复制的 7 条规则）

三张新图把这套视觉语言说全了：

### R1 · 万物皆有 3D 挤出底边
每个可交互元素 = `主色面` + `底部 6~10px 同色暗边`（不是投影，是实体挤出）+ `2~4px 亮色描边`。
绿色 CTA：面 `#6CC24A` / 底边 `#3E8E1E` / 外描边 `#FFFFFF 3px`。

### R2 · 文字双层：白填充 + 深色描边（on-color）／深蓝填充（on-white）
- 压在彩色上：`#FFFFFF` + `rgba(0,0,0,.45)` 6px round join stroke
- 压在白卡上：`#1B4C8C`（深蓝），强调数字用 `#E23B2E`（红）

### R3 · 弹窗三件套 = 白卡 + 骑跨式标题条 + 框外红 X
- 白卡 `#FFFFFF`，radius 28，外描边浅蓝 `#7EC8F0` 4px
- 标题条**骑在白卡上边缘**（上半出框），蓝色渐变 `#5BB8F5→#2E9BE8`，radius 24
- 关闭 X **在白卡右上角外侧**，红圆 `#E8352B` + 白圈，r=32

### R4 · 色彩语义严格分工
| 色 | 用途 |
|---|---|
| 绿 `#6CC24A` | 唯一确认 / 领取 / 再试一次 |
| 黄橙 `#FFB13D` | 次级操作（主页 / 分享 / 升级 / 消除） |
| 蓝 `#2E9BE8` | 标题条 / 信息 / 刷新 |
| 红 `#E8352B` | 关闭 / `+` 角标 |
| 灰 `#7A7A80` | 背景（**零信息**） |

### R5 · 背景绝对沉默
纯灰 `#6E6E75`，右上一块更亮的斜切楔形 `#8A8A92`，仅此而已。**100% 视觉预算给图案。**

### R6 · 失败页不用卡片，用"舞台"
不是白卡承载，而是：云朵 ribbon 横幅 + 大情绪角色 + 一行鼓励 + 三按钮，直接铺在暗化的玩法画面上。比白卡更有戏剧感、也更省一层遮挡。

### R7 · 豆子是「黑描边像素画」
图案的轮廓线**本身就是黑色豆子**堆出来的。每颗豆 = 圆角方块 + 顶部高光 + 深色底边。所以图案在任何背景上都自带对比度 —— 这是它敢用纯灰背景的底气，也是我方最大的缺口。

## 四、我方适配方案（解掉"美女 vs 玩法"的死结）

竞品能用纯灰背景，我们的差异化卖点却是主播立绘。上一轮的结论是这两者互斥 —— 但有第三条路：

### 立绘做「动态显影」底图

```
游玩中：立绘 亮度×0.55 + 高斯模糊 8px + 暗角
   → 背景变成"有形状的灰"，等效竞品的纯灰底，对比度拿回来
   → 同时首屏仍然是个美女剪影，点击率保住
   → 而且"看不清" = 悬念，反而强化了揭示动机

清豆进度 0%→100%：亮度 0.55→1.0，模糊 8px→0px（跟随 cleared/total 线性插值）
   → 揭示感 = 画面逐渐"亮起来 + 对上焦"，比单纯"豆子消失"强得多

过关瞬间：立绘 100% 清晰 + 全屏亮起 + 白框成品拼豆图
```

**这一条同时解决 4 个问题**：对比度、悬念、揭示爽感、首屏吸引力。且实现成本极低 —— `buildBg()` 里加一层可变 alpha 的暗色遮罩 + 预生成一张模糊版底图交叉淡入即可（小游戏端不要用实时 `filter: blur`，性能不允许）。

### 配套 5 条无条件修正（与路线无关）

1. `drawBean` 必须加 `stroke`（黑 2.5px）+ 底部暗边 —— 现在注释承诺了但没实现
2. 车改纵向：`qCarW/qCarH` `104×94` → `96×126`，圆角 `w*.26` → `w*.16`
3. `spdRect` 与 `btnRect(0)` 的 38px 重叠 → 速度独占一行（y 1073–1206）
4. 底部 158px 死区消除，按钮坐到屏幕最下沿；`qPanel`/`tray` 双层紫合并为一层
5. `palette.base` 不能是 `white`（白豆压白裙）；改 `pink` 为底色，白色降为点缀
6. 死局改两层漏斗：先复活弹窗（单 CTA），拒绝后才进失败页
7. 道具角标改红底白 `+`，`▶` 只留给纯广告位
