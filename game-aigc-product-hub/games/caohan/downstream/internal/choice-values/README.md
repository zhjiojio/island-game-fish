# 当前下游数值反馈配置

正式文件为 ../../game-config.json。本次新增陈劲好感 favor、清醒值 wisdom、勇气值 courage，图标沿用工程示例的 default/icon_favor.png、default/icon_wisdom.png、default/icon_courage.png。三项初始值约定为 0，允许负数；工程须确认初始化和图标资源可用。

44 个原始选项的逐项分值和理由见 option-values.json / option-values.md；配置中映射到 71 个可点击选项组件。9 个锁定说明没有 value。广告续播、视频播放、结局、分享、坏结局重试入口均不加分。媒体、分支条件和跳转不变，数值不参与结局判定。

## 工程必须实现并验证的结算行为

- 成功选中免费/已满足条件选项后结算一次；广告选项仅在激励成功后结算，取消、失败不能结算。
- 按本轮游戏的原始 choiceId 记录当前选项和该次增量；同选择的节点变体引用同分值，重复回调与重播不重复累加。
- 坏结局广告重试成功后，撤销上一选择已结算的三个增量，再进入对应选择节点；广告失败不撤销。重新选择后结算新选项，不能仅把新分数叠加。
- 重新开始重置分数及本轮结算记录，继续游戏恢复两者。跨周目收藏可单独保留，不继承本轮分数。

当前 JSON 只提供 valueDefinitions 与组件 value，没有擅自新增样例未定义的去重、撤销字段。配置核验不等于引擎已实现上述行为，需工程验证广告成功/失败、连点、重播、重选、存档和重开。

## 重建与版本

从已确认的无分值配置建立 game-config.before-values.json，执行 apply_values.py，再执行 verify_values.py，审核后复制候选到正式文件。不要只执行旧版导出/适配脚本覆盖正式文件，否则会丢失本次分值。template4/ 保存上一阶段格式适配；v5/ 保存媒体和 CDN 证据。本次未修改原始 v4/v5 剧本与视频，也未推送远端。
