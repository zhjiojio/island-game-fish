# 故事型关卡剧本生成规则

> 适用于所有 `mode: "story"` 的连续剧情找线索主题。  
> 全类型识别入口：`docs/全类型关卡批量生成规则.md`；识别为 `story` 后再执行本文。  
> 标准格式参考：`docs/《1808房间》第一章1-5关剧本.md`。  
> 后续生成、续写、重写剧本时，必须保持本文规定的 Markdown 层级、标题顺序和字段名称。

## 1. 输出范围识别

先判断用户要哪一种输出：

1. **单关**：只生成指定关卡，但仍使用“关卡固定格式”。
2. **单章**：出现“第X章”“X-Y关”或明确的一组关卡时，输出一个完整章节。
3. **整部剧本**：出现“完整剧本”“整个故事”“全部章节”时，按章节连续输出；每章都重复同一套章节格式。
4. **修改现有剧本**：保留原文件标题层级、字段顺序、关卡编号和空行，只修改用户点名的内容。

识别优先级：用户明确范围 > 用户给出的关卡编号 > 默认每章5关。

### 章节与关卡编号

- 默认每章5关。
- 关卡编号在整部剧本中连续，不因换章归零。
- 默认对应关系：第一章1-5关、第二章6-10关、第三章11-15关，以此类推。
- 用户指定其他范围时，以用户范围为准。
- 每章最后一关必须是阶段反转，并引出下一章；全剧最后一章改为收束最终真相。

## 2. 剧情生成规则

### 2.1 整体故事

生成前先在内部锁定：

- 剧名、类型、玩家身份和调查视角。
- 开局异常、最终真相和最终反转。
- 主要人物的关系、目的、秘密和稳定视觉特征。
- 3-6个会跨关复现的证据母题。
- 每章解决的阶段问题。

这些内容用于保证连续性，不额外改变最终 Markdown 格式。

### 2.2 五关章节节奏

默认按以下节奏推进：

1. 异常出现：发现第一批不合理痕迹。
2. 证据复现：证明异常不是偶然。
3. 谎言冲突：时间、地点或说法对不上。
4. 计划暴露：发现对方持续、主动的安排。
5. 章节反转：锁定新人物、新地点或更大的真相。

每关必须新增至少一项事实：人物、地点、时间、关系、动机、风险或旧证据的新解释。删掉某关仍不影响主线时，该关必须重写。

### 2.3 单关内容

每关必须包含：

- 开场：承接上一关，说明玩家为何进入现场。
- 调查方向：固定3条，只写模糊目标，禁止公布答案名。
- 搜证内容：每条包含答案名、位置表现和玩家旁白。
- 通关揭示：总结本关证据共同证明的结论。
- 下一关钩子：给出可执行的下一步，不写空泛悬念。

答案名、位置表现、玩家旁白必须表达不同信息：

- 答案名负责确认物品。
- 位置表现负责指导生图和标注。
- 玩家旁白负责解释证据、推进剧情。

## 3. 线索与难度

### 3.1 数量

- 教学或章节首关：5-6条。
- 普通推进关：6-7条。
- 章节中后段：7-8条。
- 章节高潮：8-9条。

### 3.2 难度

- 每关保留1条较明显线索，其余线索通过同色伪装、透视缩小、生活杂物干扰、前中后景切换或部分遮挡增加难度。
- 每条线索只能对应一个唯一答案物体和一个点击区；禁止复制同一线索物、把一个答案拆成多个目标，或为同一线索设置多个热区。
- 线索必须分散在不同高度、景深和区域。
- 不得全部放在同一个箱子、桌面、抽屉或画面四角。
- 任意两个答案物体和点击区域不得相交、包含或重叠。
- 禁止用坐标偏移、超小热区、完全遮挡、过暗或模糊画面制造难度。
- 人物可以出镜推动剧情，但默认不作为答案，也不能遮挡线索。

## 4. 文案规则

- 所有玩家可见文字使用简体中文和阿拉伯数字。
- 不使用英文、日文、繁体字、拼音、乱码或真实品牌名。
- 关卡名不超过8个汉字，不把“困难、地狱、BOSS”等难度词写进标题。
- 开场正文只写1个自然段，最多40个可见字符；标点、数字均计入，禁止手动换行。
- 调查方向固定3条，不能出现本关准确答案名。
- 玩家旁白优先使用第一人称即时反应，并明确证据意义。
- 通关揭示只写1个自然段，最多40个可见字符；禁止 `\n` 或手动换行，只保留本关结论。
- 下一关钩子与通关揭示分开，使用一句不超过40个可见字符的地址、消息、声音、人物行动或新物证。

## 5. Markdown 固定格式

### 5.1 不可变规则

- 不增加目录、前言、配置说明、JSON、坐标、prop ID、提示词或制作备注。
- 不使用表格代替正文。
- 不改变标题级别、标题名称或字段顺序。
- 一级标题只用于章节标题；二级标题用于章节信息和关卡；三级标题用于关卡内部字段。
- 章节之间用一行 `---` 分隔；关卡之间也用一行 `---` 分隔。
- 列表缩进、粗体答案名和两条子项的写法必须保持一致。
- 输出整部剧本时，直接连续拼接多个“章节固定模板”，不额外套一层新格式。

### 5.2 单章固定模板

以下结构必须原样复用，只替换尖括号中的内容：

```markdown
# 《<剧名>》第<中文章节号>章：<章节名>

## 故事定位

- 类型：<类型与情绪>。
- 玩家身份：<玩家身份与调查视角>。
- 核心嫌疑人：<本章主要怀疑对象或未知身份>。
- 重复视觉线索：<跨关证据母题>。
- 第<中文章节号>章目标：<本章要证明或找到的结果>。

## 第<中文章节号>章梗概

<用2-4个自然段概括本章起因、升级、阶段真相和结尾去向。>

---

## 第<全局关卡号>关：<关卡名>

### 开场

<单段且不超过40个可见字符：承接上一关、进入现场并点明异常。>

### 调查方向

1. <模糊调查目标一>。
2. <模糊调查目标二>。
3. <模糊调查目标三>。

### 搜证内容

1. **<答案名>**
   - 位置表现：<物体在画面中的自然位置和视觉状态>。
   - <玩家名>旁白：“<即时判断与剧情意义>”

2. **<答案名>**
   - 位置表现：<物体在画面中的自然位置和视觉状态>。
   - <玩家名>旁白：“<即时判断与剧情意义>”

<按本关线索数量继续编号。>

### 通关揭示

<单段且不超过40个可见字符：本关证据共同证明的结论。>

### 下一关钩子

<一句具体、可执行且不超过40个可见字符的钩子。>

---
```

### 5.3 章节最后一关

章节最后一关仍保留“开场、调查方向、搜证内容、通关揭示”，但不再使用“下一关钩子”，改为：

```markdown
### 第<中文章节号>章结尾

<用2-3个自然段写本章收束、人物行动和新场景。>

## 第<下一中文章节号>章钩子

<一句具体对白、消息或新发现。>
```

如果是全剧最后一章，则最后一个二级标题改为：

```markdown
## 全剧结局

<收束最终真相、人物选择和情绪落点。>
```

### 5.4 整部剧本格式

- 按章节顺序重复“单章固定模板”。
- 每章从独立的一级标题开始，例如 `# 《剧名》第二章：章节名`。
- 下一章的第一个关卡号必须承接上一章。
- 上一章的“第X章钩子”必须被下一章开场直接承接。
- 不在文档顶部增加“完整剧本”“总目录”等额外层级。

## 6. 生成与修改流程

1. 识别输出范围：单关、单章或整部剧本。
2. 锁定最终真相、章节目标和角色关系。
3. 按章节节奏列出逐关信息增量。
4. 按固定模板生成正文。
5. 检查线索数量、分布、难度和剧情作用。
6. 统计开场、通关揭示和下一关钩子的可见字符数，任何一项超过40都必须压缩。
7. 检查开场和通关揭示没有手动换行，上一关钩子被下一关承接。
8. 对照参考文件检查标题层级、顺序、空行和列表缩进。
9. 只交付剧本 Markdown；配置下发、生图和标注另走各自流程。

## 7. 输出前检查

- [ ] 输出范围和章节、关卡编号正确。
- [ ] Markdown 标题层级与参考文件一致。
- [ ] 每章都有“故事定位”和“第X章梗概”。
- [ ] 每关字段顺序完全一致。
- [ ] 每关有且只有3条调查方向，且没有泄露答案名。
- [ ] 开场为单段且不超过40个可见字符，没有手动换行。
- [ ] 每条证据都有答案名、位置表现和玩家旁白。
- [ ] 每条线索只有一个唯一答案物体和一个点击区，没有重复线索或拆分热区。
- [ ] 每关都有信息增量和明确结论。
- [ ] 通关揭示为单段且不超过40个可见字符，没有 `\n`；下一关钩子单独展示且不超过40个可见字符。
- [ ] 非章节末关有“下一关钩子”。
- [ ] 章节末关有“第X章结尾”和下一章钩子；全剧末章有“全剧结局”。
- [ ] 线索没有集中在同一区域，也没有相交或重叠。
- [ ] 全部可见文字为简体中文。
- [ ] 文档中没有配置字段、JSON、坐标或制作说明。
